# Hysteria 2 Manager v3.2

Интерактивный менеджер пользователей для [Hysteria 2](https://hysteria.network/) VPN-сервера.

## Возможности

Полноценная панель управления Hysteria 2 в терминале: пользователи, статистика,
подписки и кластер из нескольких серверов — без ручной правки конфигов.

- 🚀 **Управление без разрыва VPN** — добавление, отключение, удаление и смена пароля применяются мгновенно, без перезапуска сервера
- 🌐 **Мультисервер (кластер)** — одна ссылка-подписка собирает ключи со **всех** серверов, автообновление на стороне клиента
- 🟢 **Индикатор загрузки серверов** в подписке — клиент видит онлайн каждого сервера и выбирает, к какому подключиться
- 🛡 **Лимиты устройств** — глобальные и персональные, с жёсткой проверкой на входе и мягким киком лишних сессий
- 📊 **Статистика по всему кластеру** — трафик, онлайн, скорость и IP-трекинг (анти-шаринг аккаунтов)
- ⏰ **Сроки действия аккаунтов** с автоматическим отключением по истечении
- 🔗 **Готовые ссылки** `hysteria2://` и **конфиги sing-box** (TUN / SOCKS) прямо из меню
- 🕵️ **Скрытие IP сервера** — маскировка под SNI + опциональный релей (фронт-VPS)
- ⚙️ **Установка одной командой** — BBR, firewall, сертификаты и HTTPS-подписка (Caddy) настраиваются автоматически
- ♻️ **Самовосстановление и авто-миграции** — подписка чинится сама, обновления применяются без ручных шагов

👉 Полный перечень — в разделе [**Все возможности**](#все-возможности) ниже.

## Требования

- Debian / Ubuntu (тестировалось на Debian 13)
- root-доступ
- Все зависимости устанавливаются автоматически

## Установка / переустановка

Та же команда работает и для первой установки, и для обновления — скрипт сам определит состояние сервера:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/CABi-Code/Hysteria2-manager/main/install.sh)
```

> ⚠️ Используйте именно `bash <(curl ...)`, а не `curl ... | bash` — установщику нужен интерактивный TTY для запроса параметров. Скрипт также сам пробует переключиться на `/dev/tty`, но `bash <(...)` гарантированно работает.

Если Hysteria 2 уже установлена, скрипт спросит:

| Режим | Что делает |
|-------|-----------|
| **1) Обновить только менеджер** | Скачивает свежие `hy2-manager.sh` и `lib/*.sh`, обновляет симлинк, ставит лог-каталог. **Hysteria, конфиг, сертификаты и пользователи не трогаются.** |
| **2) Полная переустановка** | Останавливает сервис, удаляет Hysteria, `/etc/hysteria/`, `/opt/hy2-manager`, `/var/log/hy2-manager`, чистит crontab — затем устанавливает всё с нуля. **Все пользователи и статистика теряются.** |
| **3) Отмена** | Выйти, ничего не меняя. |

При свежей установке скрипт интерактивно спросит:

- **Порт** — UDP-порт для Hysteria (по умолчанию случайный 10000-65000)
- **Домен для маскировки** — SNI для TLS (по умолчанию `www.twitch.tv`)
- **OBFS-пароль** — пароль обфускации Salamander (генерируется автоматически)
- **Имя первого пользователя** — будет создан с 64-символьным паролем

После установки менеджер доступен командой `hy2-manager`.

### Альтернативные источники

Если форкнули репозиторий, можно указать свой URL через переменную окружения:

```bash

sudo REPO_URL="https://raw.githubusercontent.com/USERNAME/REPO/BRANCH" bash <(curl -fsSL https://raw.githubusercontent.com/USERNAME/REPO/BRANCH/install.sh)

```

### Что делает install.sh

1. Обновляет систему, ставит зависимости (`curl`, `jq`, `pwgen`, `openssl`, `cron`)
2. Включает BBR (ускорение TCP)
3. Открывает UDP-порт (`ufw allow` если активен, либо корректное правило nftables)
4. Скачивает и устанавливает Hysteria 2 (с проверкой успешности загрузки)
5. Гарантирует наличие пользователя `hysteria` и проверяет, что приватный ключ читается
6. Генерирует самоподписанный сертификат (10 лет)
7. Создаёт `config.yaml` с обфускацией Salamander, QUIC-тюнингом и trafficStats API (mode 640)
8. Скачивает менеджер из репозитория в `/opt/hy2-manager`, создаёт симлинк `/usr/local/bin/hy2-manager`
9. Запускает `hysteria-server.service`, проверяет что он `active` и слушает UDP-порт
10. Выводит готовую `hysteria2://` ссылку для клиента

## Структура проекта

```
install.sh               # Полная установка: Hysteria 2 + конфиг + менеджер
hy2-manager.sh           # Точка входа: CLI-аргументы, инициализация, главное меню
lib/
  config.sh              # Конфигурация, пути к файлам, чтение config.yaml
  deps.sh                # Проверка и установка зависимостей
  api.sh                 # Работа с Hysteria trafficStats API
  traffic.sh             # Сбор и форматирование статистики трафика
  ip_tracking.sh         # Сбор и анализ IP-адресов пользователей
  online.sh              # Онлайн-статус через API
  expiry.sh              # Управление сроками действия
  users.sh               # CRUD-операции над пользователями
  cron.sh                # Настройка cron-задач
  migration.sh           # Автомиграции auth: password -> userpass -> command
  ui.sh                  # Интерфейс: таблицы, подменю, меню ссылок, ремонт
```

### Аутентификация без перезапусков

Менеджер использует внешнюю аутентификацию Hysteria 2 (`auth.type: command`):
сервер на каждое подключение вызывает скрипт `hysteria-auth.sh`, который
сверяет пару `логин:пароль` с базой `users.db`. Благодаря этому **добавление,
удаление, отключение и смена пароля применяются мгновенно — без перезапуска
Hysteria** (а значит, без обрыва VPN у остальных клиентов).

При обновлении со старого формата (`auth.type: userpass`, пользователи прямо в
конфиге) выполняется разовая автомиграция: пользователи переносятся в `users.db`,
конфиг переключается на `command`, и сервер перезапускается **один раз**. Ссылки
клиентов при этом не меняются — формат `hysteria2://логин:пароль@...` тот же.

## Использование

### Интерактивный режим

```bash
sudo hy2-manager
```

Откроется главное меню:

```
╔══════════════════════════════════════════════════════════════╗
║                   Hysteria 2 Manager v3.1                    ║
╠══════════════════════════════════════════════════════════════╣
║ IP сервера      : 203.0.113.1
║ Порт            : 11478
║ SNI / Маскировка: www.twitch.tv
║ OBFS-пароль     : abc123def456ghij7890...
║ Пользователей   : 5 (активных: 3, онлайн: 1)
╚══════════════════════════════════════════════════════════════╝

  1. ➕ Добавить нового пользователя
  2. 👥 Пользователи (статистика, IP, действия)
  3. 🔗 Получить ссылку
  4. 🚪 Выход
```

### CLI-режим (для cron)

```bash
# Сбор трафика и IP-адресов
sudo hy2-manager --collect

# Проверка и отключение просроченных пользователей
sudo hy2-manager --check-expiry

# Синхронизация ключей с другими нодами кластера + пересборка подписок
sudo hy2-manager --cluster-sync

# Частый обмен онлайном + применение лимита устройств по кластеру (раз в минуту)
sudo hy2-manager --online-sync
```

Cron-задачи настраиваются автоматически при первом запуске.

## Все возможности

Подробный перечень по разделам. Ключевые темы (подписка, кластер, лимиты) детально
разобраны в отдельных разделах ниже.

### 🔐 Сервер и установка
- **Hysteria 2 (QUIC/UDP)** с обфускацией **Salamander** (obfs-password)
- **Самоподписанный сертификат на 10 лет** и маскировка под произвольный **SNI** (по умолчанию `www.twitch.tv`)
- **BBR** (ускорение TCP) включается при установке
- **Авто-настройка firewall** (ufw/nftables): UDP-порт Hysteria + 80/443 для подписки
- Установщик в **3 режимах**: чистая установка / обновление только менеджера / полная переустановка
- Настраиваемый порт; свой форк — через переменную `REPO_URL`
- Версия менеджера вынесена в отдельный файл `VERSION` и подставляется в баннеры

### 👤 Пользователи
- Добавление с авто-генерацией пароля (64 символа), **применяется мгновенно без перезапуска** (`auth.type: command`)
- Отключение / включение без удаления, смена пароля, удаление, сброс статистики
- **Сроки действия** в днях от текущей даты; авто-проверка каждые 6 ч и авто-отключение просроченных
- Валидация имён и защита зарезервированных (конфликтующих с YAML) имён
- Готовая ссылка `hysteria2://` для клиентов (Hiddify, Nekobox, Streisand и др.)
- **Экспорт конфига sing-box** — TUN (полный туннель) или SOCKS/mixed (локальный прокси `127.0.0.1:1080`), вывод на экран и сохранение во временный файл (mode 600)

### 📊 Статистика и мониторинг
- **Трафик** по каждому юзеру (отправлено/получено) через Hysteria API
- **Онлайн-статус** — кто в сети и сколько подключений; живое обновление меню
- **Текущая скорость** (B/s, KiB/s, MiB/s) — в карточке юзера и колонкой в таблице
- **IP-трекинг** — уникальные IP, первый/последний визит, счётчик (справочно; много IP при роуминге — это норма, а не шаринг)
- **Кластерные сводки** — онлайн, трафик и IP агрегируются со **всех** нод
- Учёт IP, скачавших ссылку-подписку (`/sub/<token>`), по всему кластеру
- **Автообновление без мигания** — меню перерисовываются каждые ~2 с поверх старого кадра (без `clear`)
- **Навигация стрелками** `←` / `→` по страницам списка; активные клиенты — вверху

### 🌐 Подписка
- Персональная ссылка `/sub/<token>` по **HTTPS (Caddy)**, автообновление в клиенте
- Настройка названия профиля и интервала обновления
- **Шаблон подписи ключа** с плейсхолдерами `{label}` `{user}` `{name}` `{online}`
- **`{online}` — индикатор загрузки сервера**: у ключа каждой ноды показан онлайн именно её сервера; значения подтягиваются со всех нод кластера (~1 мин)
- **Метка ноды** с эмодзи/флагами (напр. «🇩🇪 Германия-1»)
- **Доп. ссылки подписки** для одного юзера (несколько токенов)
- **Домен подключения** в ссылке — чтобы скрыть «голый» IP ноды
- **Диагностика подписки** (DNS → сервер → порты → Caddy → сертификат → пиры) и диагностика профиля по кластеру
- **Самовосстановление**: если Caddy лёг или конфиг битый — порты открываются и конфиг пересобирается автоматически

### 🕸 Кластер (несколько серверов)
- Создание кластера (join-токен), подключение по токену, добавление пира вручную
- **Gossip** реестра нод — ноды узнают друг о друге автоматически
- **Кластерные пользователи** — живут на всех нодах (свой пароль на каждой), ключи собираются в одну подписку
- **Единая ссылка-подписка** со всех серверов сразу; недоступный пир просто пропускается
- Pull-синхронизация разделов: ключи, токены, реестр, состояния, IP, сроки, настройки, лимиты
- **Режимы синхронизации**: `ask` (спрашивать), `auto` (сразу), `cron` (по расписанию)
- **Last-write-wins** для общих настроек и сроков с защитой от расхождения часов между нодами
- Единая точка правды для распространения отключения/удаления/сроков по кластеру
- Полная синхронизация раз в 5 мин, обмен онлайном раз в 1 мин, ручная синхронизация из любого меню

### 🛡 Лимиты устройств и антиабуз
- **Глобальный лимит пула** + **лимит на ноду** + **персональный лимит** юзера (эффективный = минимум из них)
- **Жёсткая проверка** — держит **активный трафик** подписки только на «первой» ноде: параллельное активное использование на других нодах обрезается (по реальной скорости за минуту, не по пингам). Смена ноды при этом работает без блокировок
- **Авто-антиабуз** — балл «шаринга» 0–100 копится, когда подписку **активно** используют сразу на нескольких нодах, и сам угасает; при превышении порога жёсткая проверка **включается автоматически на время**. Ноды раз в час обмениваются состоянием и сходятся к общему решению
- **Мягкий кик** лишних сессий по cron; ручной кик сессии на ноде
- Индикатор ⚠️ в списке пользователей при превышении лимита

### 🕵️ Скрытие IP и релей
- Маскировка трафика под TLS-SNI
- **Релей (фронт-VPS)** — генерирует скрипт `iptables` DNAT (UDP Hysteria + TCP 80/443), чтобы клиенты и DNS видели IP релея, а не реальной ноды

### ♻️ Надёжность и обслуживание
- **Мгновенное применение** правок пользователей без перезапуска (VPN не рвётся у остальных)
- **Ручной перезапуск** для изменений, которые его требуют (порт, SNI) — копятся и применяются осознанно
- **Авто-миграции** при обновлении (режим аутентификации, формат лимитов устройств)
- **Cron-задачи** настраиваются сами: сбор статистики (30 мин), проверка сроков (6 ч), синхронизация кластера (5 мин), обмен онлайном (1 мин), коррекция анти-абуза (1 ч)
- Модульная архитектура (`lib/*.sh`) и лог ошибок в `/var/log/hy2-manager`

## Единая подписка / мультисервер

Можно поставить менеджер на несколько серверов и выдавать пользователю **одну
ссылку-подписку** `https://<домен>/sub/<токен>`, в которой собраны ключи со **всех**
серверов. Подписку понимают Hiddify, Nekobox, sing-box, Streisand и т.п.; список
автоматически обновляется на стороне клиента.

Как это работает: HTTPS-подписку раздаёт **Caddy** (авто-сертификат Let's Encrypt по
домену ноды). Менеджер генерирует статические файлы подписки и обменивается ключами с
другими нодами через защищённый заголовком `X-Cluster-Auth` манифест. Каждая нода держит
полный кэш ключей кластера, поэтому **любая** нода отдаёт объединённую подписку (если пир
недоступен — его ключи просто пропускаются). Активного перезапуска не требуется.

Настройка — в меню **Настройки → 🌐 Подписка / Кластер**:

1. **Настроить домен** — указать домен ноды (A-запись на её IP); ставится Caddy, включается подписка.
2. **Создать кластер** (на первой ноде) → получить join-токен.
3. **Подключиться к кластеру** (на остальных) → вставить токен; затем на первой ноде один раз
   добавить домен новой ноды (**Добавить пир**).
4. Заводите пользователя **тем же именем** на каждой ноде — его ключи попадут в общую подписку.
   Ссылку-подписку для пользователя смотрите в его карточке (пункт «🌐 Ссылка-подписка»).

Требуется домен/субдомен на каждую ноду и открытые порты **80/tcp** и **443/tcp** (ACME + HTTPS).

## Лимиты устройств, доп. ссылки и жёсткая проверка

Ограничение числа устройств на подписку строится на трёх уровнях (персональный —
приоритетнее глобальных):

- **Глобальные лимиты** — в **Настройки → 🌐 Подписка / Кластер → Глобальные лимиты**:
  - *на пул* — максимум одновременных подключений на подписку СУММАРНО по всему кластеру;
  - *на ноду* — максимум на ОДНУ ноду (страхует от «размазывания» подписки и багов
    синхронизации, например: нода = 1, пул = 2).
  Оба **синхронизируются автоматически** по кластеру (задавать на каждой ноде не нужно).
- **Персональное «кол-во устройств»** у каждого юзера (по умолчанию **1**) — в его
  карточке, пункт **🔢 Устройства и ссылки**. Оно **приоритетнее** глобальных лимитов и
  задаёт: сколько одновременных подключений разрешено И сколько ссылок подписки можно
  создать (по одной на устройство/человека). Значение `0` = «использовать глобальный лимит».
- **Доп. ссылки подписки** — там же: получить/удалить дополнительную ссылку
  `https://<домен>/sub/<токен>` (все ссылки юзера отдают одни и те же ключи). Рядом с
  каждой ссылкой показано число уникальных IP, скачавших её за 7 дней (из access-лога Caddy) —
  помогает заметить шаринг. Основную ссылку удалить нельзя.
- **Прервать сессию** — ручной кик всех сессий юзера на текущей ноде.
- **Жёсткая проверка** (per-user, по умолчанию выкл.) — держит **активный трафик**
  подписки только на одной ноде за раз. Механика **traffic-based** (не на этапе auth):
  раз в минуту менеджер смотрит, на каких нодах юзер реально гонит трафик (скорость за
  минуту ≥ порога — не пинги/keepalive). Если активных нод больше лимита устройств —
  оставляет ту, что стала активна **раньше** («первую»), а сессии на «лишних» кикает.
  Аутентификация при этом НИКОГО не отклоняет, поэтому переподключения и **смена ноды
  работают без блокировок** (старая нода уходит в неактив — новая становится
  единственной активной). Порог активности — `ACTIVITY_THRESHOLD_BPS` (по умолч. 4096 B/s).

### Авто-антиабуз (авто-включение жёсткой проверки)

Жёсткую проверку не обязательно держать включённой руками — есть **балльная система
подозрения на шаринг**:

- **Нарушение** — это когда подписку **одновременно активно** используют (по текущей
  скорости каждой ноды) больше, чем разрешено устройств. Учитывается **не объём
  трафика**, а факт параллельной активности на нескольких нодах. Число IP на
  подозрение **не влияет** (роуминг и семья дома — это норма).
- За минуты нарушения юзеру копятся **баллы (0–100)**, которые сами **угасают** со
  временем (`ABUSE_DECAY_PER_HOUR`/час). При достижении порога (`ABUSE_SCORE_HIGH`,
  по умолч. 60) **на время** (`ABUSE_AUTO_HC_HOURS`, по умолч. 6 ч) включается
  жёсткая проверка. Балл виден в карточке юзера.
- **Обмен по кластеру.** Сырые данные (кто на какой ноде сейчас активен по трафику)
  расходятся ежеминутно вместе со статистикой. Раз в час (`--antiabuse`) каждая нода
  делает **коррекцию** балла и публикует итог; ноды сливают состояние (балл — по
  свежей метке, окно авто-проверки и пики — максимумом) и **сходятся к общему решению**.
- Всё **fail-safe**: при недоступности API/пиров ничего не кикается и защита не
  снимается раньше времени. Пороги/веса тюнятся через env (см. `lib/config.sh`).

Когда подключений больше лимита, в списке пользователей символ онлайна меняется на **⚠️**.
Мягкое отключение лишних сессий по числу подключений (кик по cron, ~1 мин) включается,
когда задан хотя бы один глобальный лимит; юзеров с жёсткой проверкой (ручной или авто)
ведёт traffic-based механизм, а не счётчик подключений.

**Индикатор загрузки сервера в подписи.** В шаблоне подписи (Оформление подписки)
доступен плейсхолдер `{online}` — **общий онлайн того сервера**, к которому относится
ключ (сколько пользователей сейчас онлайн на этой ноде). У ключа каждой ноды в подписке
стоит онлайн именно её сервера, поэтому клиент видит загрузку всех серверов и выбирает,
к какому подключиться. Например, шаблон `{label} [🟢 {online}]` покажет рядом с каждым
сервером его текущий онлайн. Значения чужих нод менеджер подтягивает со всех серверов
кластера периодически (~1 мин при активной online-синхронизации) и обновляет в подписке;
клиент видит их после обновления подписки. Полный набор плейсхолдеров:
`{label}` `{user}` `{name}` `{online}`.

**Единая синхронизация.** Во всех разделах меню есть пункт **🔄 Получить синхронизацию
(локально)** (в списке пользователей — клавиша `s`). Он запускает одну общую функцию
синхронизации: публикует наши данные, забирает данные со всех пиров и применяет их
локально, показывая подробный лог по каждой ноде (подключение → приём разделов →
применено) и итог «на связи N из M». Модель gossip — pull: наши изменения появятся на
каждом пире, когда он выполнит свою синхронизацию (авто ~1 мин).

## Данные

Все данные хранятся в `/etc/hysteria/manager/`:

| Файл | Описание |
|------|----------|
| `users.db` | База активных пользователей для аутентификации (user:password) |
| `hysteria-auth.sh` | Скрипт внешней аутентификации (вызывается Hysteria) |
| `stats.dat` | Статистика трафика (user\|tx\|rx) |
| `ips.dat` | IP-адреса (user\|ip\|first_seen\|last_seen\|count) |
| `expiry.dat` | Сроки действия (user\|YYYY-MM-DD) |
| `disabled.dat` | Отключённые пользователи (user\|password) |
| `api_secret` | Секрет trafficStats API |
| `node.conf` | Параметры ноды для подписки (имя, домен) |
| `cluster.conf` | Реестр нод кластера (name\|host) |
| `cluster.secret` | Общий секрет кластера (аутентификация между нодами) |
| `subtokens.db` | Токены подписки пользователей (user:token, несколько на юзера) |
| `userlimits.dat` | Персональные лимиты (user\|устройства\|жёсткая_проверка) |
| `subips.dat` | IP скачиваний подписки по токену (token\|ip\|first\|last\|count) |
| `authlimits.dat` | Снимок лимитов (устар.: auth больше не режет по числу сессий) |
| `activity.dat` | Активность по трафику (user\|active\|active_since\|rate) для жёсткой проверки |
| `abuse.dat` | Анти-абуз (user\|балл\|метка\|окно_авто\|пик_нод\|мин_нарушений), синхр. по кластеру |
| `peers/*.manifest` | Кэш ключей других нод кластера |
| `peers/*.abuse` | Кэш состояния анти-абуза других нод |

Статика подписки (раздаётся Caddy) лежит отдельно в `/var/www/hy2sub/` —
её читает процесс `caddy`, не `hysteria`.

## Логи

Ошибки самого менеджера пишутся в `/var/log/hy2-manager/error.log`. Подключения пользователей сюда не логируются — для них используйте журнал systemd:

```bash
sudo journalctl -u hysteria-server -f
sudo tail -f /var/log/hy2-manager/error.log
```
