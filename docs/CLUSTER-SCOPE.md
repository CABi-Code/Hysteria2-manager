# Область действия настроек в кластере

Что уезжает на другие ноды, что остаётся локальным и как добавлять новое поле
синхронизации, не повторяя баг «локальную настройку разнесло по кластеру».

Код: `lib/cluster.sh` (публикация и применение), `lib/limits.sh`,
`lib/expiry.sh`, `lib/node.sh` (значения), `lib/perf.sh` (лимиты ядра).

## Два вида профилей

| | Локальный | Кластерный |
|---|---|---|
| Признак | имени нет ни в одном roster | имя есть в `cluster_users` этой ноды **или** в `peers/*.roster` (`is_cluster_user`) |
| Кто заводит | «Создать пользователя» в TUI | пункт 10 в меню юзера (`cluster_share_user`), провижининг через API/бота (`bot_provision_user`), roster пира (`cluster_apply_roster`) |
| Живёт | только на своей ноде | на всех нодах, свой пароль на каждой |
| Срок, лимиты, тариф скорости | только своя нода | LWW по кластеру |

**Провижининг через API/мини-апп/бота всегда даёт КЛАСТЕРНЫЙ профиль** —
клиент купил доступ, он должен работать везде. Локальный профиль заводится
только руками в TUI.

Вернуть ошибочно окластеренный профиль в локальные — пункт 15 в меню юзера
(снимает метку на этой ноде). Пока имя остаётся в roster пира, ноды будут
заводить его снова: метку надо снять и там, пункт 15 показывает, где именно.

## Что синхронизируется

| Данные | Файл в `/cluster/` | Область | Слияние |
|---|---|---|---|
| Жизненный цикл (active/disabled/deleted) | `state` | кластерные | LWW по ts, `deleted` — tombstone |
| Ростер | `roster` | кластерные | объединение |
| Срок действия | `expiry` | кластерные (`cluster_users_all`) | LWW по ts |
| Персональные лимиты: устройства, hardcheck, тариф скорости | `userlimits` | **кластерные** | LWW по ts |
| Оформление подписки (title, шаблон, интервал) | `settings` | нода целиком | LWW по ts |
| Сброс ключей | `pwreset` | кластерные | LWW по ts |
| Привязки Telegram | `tgbind` | все | LWW по tg_id |
| Анти-абуз, free-план, статистика, IP, скорость | `abuse`, `freeplan`, `stats`, `ips`, `rates` | все | максимум/LWW по полям |

Не синхронизируется вообще: параметры производительности ноды (`lib/perf.sh` —
глобальный kernel-лимит, QUIC-окна, CPUQuota: зависят от железа), `NODE_LABEL`,
домен, порты, демо-профили (`lib/demo.sh` — живут одну ноду).

## Правило для нового синхронизируемого поля

1. **Публикуем только то, что кластерное по своей природе.** Источник имён —
   `cluster_users_all`, а не `get_all_users`. Иначе локальный профиль
   (в т.ч. чужой тестовый) начнёт диктовать настройки всему кластеру.
2. **Применяем, только если объект есть у нас**: `db_user_exists "$u" ||
   is_user_disabled "$u" || continue`. Без этого запись оседает призраком в
   локальном файле.
3. **Не репаблишим то, что не применили.** Применённая запись публикуется
   дальше — значит призрак становится бессмертным: локальное удаление обнуляет
   ts, а копия с пира (ts > 0) возвращает запись на следующем sync, включая
   новый профиль с тем же именем.
4. **LWW по ts, свой ts не перебиваем.** Применяем строго при `ts > localts`
   и запоминаем ЧУЖОЙ ts (`set_*` с явным ts) — иначе обратная волна.
5. **UI не обещает того, чего не делает.** Если действие не выходит за ноду —
   так и пишем и не предлагаем синхронизацию (см. меню скорости,
   `lib/ui_devices.sh`).

Проверка правил 1–3 — `tests/test-userlimits-sync.sh` (эталон для новых полей),
LWW — `tests/test-pwreset.sh`.
