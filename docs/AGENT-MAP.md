# Карта проекта для ИИ-агента

Один файл, после которого можно править менеджер, **не читая десятки модулей**.
Здесь — как всё устроено и куда смотреть; «тема → файл кода» — в корневом
[CLAUDE.md](../CLAUDE.md), «тема → документ» — в [guide/README.md](guide/README.md),
«что сломано» — в [issues/README.md](issues/README.md).

Порядок работы: этот файл → документ темы → **только нужные функции** кода.
Список функций модуля — одной командой, без чтения файла:
`grep -n '^[a-z_A-Z0-9]*() *{' lib/<модуль>.sh`.

## 1. Что это за программа

Набор bash-модулей без постоянного процесса. Вся работа — **короткие запуски**
`hy2-manager.sh --<режим>` из крона и таймера, плюс три демона: бот
(`--bot-daemon`), Web API (`webapi/hy2-webapi.py`) и ядра протоколов (Hysteria,
Xray, sing-box — чужие бинарники, менеджер пишет им конфиги). Запуск без
аргументов — интерактивное меню.

Каждый запуск: `source` всех модулей из `_required_libs` (0,15 с) → ветка
режима → `exit`. **Состояния в памяти нет**: всё между запусками лежит в файлах
`DATA_DIR` (`/etc/hysteria/manager`), по строке на запись, поля через `|`, `:`
или табуляцию.

Отсюда три правила, которые нарушаются чаще всего:

1. **Рабочее дерево = прод.** Крон исполняет `/opt/hy2-manager` напрямую;
   сохранённая правка работает через минуту. Сначала тест в песочнице, потом
   правка.
2. **Форк — единица стоимости.** Нода — 1 vCPU. `$(...)`, конвейер и внешняя
   команда в цикле по юзерам × токенам дают тысячи форков и десятки секунд
   ([guide/CRON.md](guide/CRON.md) §3). Один `awk` по файлу вместо `grep` на юзера.
3. **Половина логики исполняется у соседа.** Правка, доехавшая только сюда,
   выглядит рабочей. Соседи обновляются с GitHub `main` (`--cluster-update`).

## 2. Режимы запуска

| Режим | Каденс | Что делает (главные вызовы) |
|---|---|---|
| `--online-sync` | cron, 2 мин | миграции, `cluster_online_sync` (онлайн, лимит устройств, справка о себе), free-план, демо, `write_authlimits`, классы скорости |
| `--cluster-sync` | cron, 5 мин | `cluster_sync`: выложить свои разделы → забрать разделы пиров → `cluster_apply_*` → `regen_subscriptions` |
| `--collect` | cron, 30 мин | трафик, адреса из журналов, сертификаты протоколов, публикация адресов, метла по временным файлам |
| `--rates-tick` | systemd-таймер, 15 с | спидометр, обмен скоростью, классы tc |
| `--notify-sweep` | cron, 5 мин | напоминания об истечении, «чужое устройство» |
| `--ym-poll` | cron, 1 мин | оплаты ЮMoney |
| `--antiabuse` | cron, 1 час | балл шаринга |
| `--check-expiry` | cron, 6 ч | отключение просроченных |
| `--sub-refresh` | по просьбе | фоновый полный перевыпуск подписок (`sub_refresh_bg`) |
| `--daily-report`, `--ruprobe`, `--watch` | cron оператора, одна нода | печатают сообщение в stdout, доставку вешает оператор |
| `--health` | руками | картина кластера одной командой |
| `--cluster-update`, `--self-update` | руками / по просьбе соседа | обновление менеджера |
| без аргументов | человек | меню (`lib/ui*.sh`) |

Каждая ветка начинается с `cron_lock <режим>` (один живой прогон, лишний тик
пропускается) и у трёх главных заканчивается `cron_done <режим>` (отметка
финиша для самодиагноза). Новый режим — ветка в `hy2-manager.sh` по образцу
соседних; расписание — `setup_cron` в `lib/cron.sh`.

## 3. Данные: где что лежит

Пути и форматы объявлены в `lib/config.sh` — это единственное место, где их
смотреть. Главное:

| Файл | Формат | Что |
|---|---|---|
| `users.db` | `user:password` | активные профили — источник правды для ядер |
| `disabled.dat` | `user\|password` | отключённые (пароль хранится для возврата) |
| `expiry.dat`, `expiry_ts.dat` | `user\|дата`, `user\|ts` | срок действия и метка его правки |
| `userlimits.dat` | `user\|устройств\|hardcheck\|…` | персональные лимиты |
| `stats.dat`, `speed.dat`, `rates.dat`, `activity.dat` | `user\|…` | трафик, скорость, активность |
| `ips.dat`, `subips.dat`, `subapps.dat` | `ключ\|хэш_адреса\|…` | адреса только **хэшем** (P-176) |
| `subtokens.db` | `user:token` | токены подписки; первая строка юзера — основной |
| `cluster.conf`, `cluster.secret` | `имя\|хост`, секрет | реестр пиров и общий секрет |
| `cluster_state.dat` | `user\|active/disabled/deleted\|ts` | точка правды жизненного цикла (LWW по ts) |
| `cluster_users` | имя на строку | ростер: профили, живущие на всех нодах |
| `peers/<имя>.<раздел>` | как у автора | кэш разделов пира; пишет **только** `peer_pull` |
| `node.conf`, `protocols.conf`, `bot.conf`, `webapi.conf` | `КЛЮЧ=значение` | настройки; читать через `conf_get` |
| `health.dat`, `.*.done`, `.*.lock` | — | самодиагноз, отметки и замки кронов |

Веб-корень (`/var/www/hy2sub`): `sub/<token>` — готовые подписки (base64),
`cluster/<раздел>` — то, что нода отдаёт соседям.

Правила работы с файлами данных:

- строка по ключу — `row_by_key`, `fld_by_key`, `conf_get` (`lib/config.sh`),
  а не `grep | cut` в цикле;
- запись — во временный файл и `mv`; общие счётчики — только через `_stats_add`
  (`lib/traffic.sh`, под `flock`);
- имя профиля и токен перед подстановкой в путь, `sed` или `rm` —
  `valid_name`, `valid_token`;
- временные файлы называть `*.tmp.<pid>` — их подметает `--collect`.

## 4. Кластер

Ноды равноправны, центра нет. Два канала ([guide/CLUSTER-CHANNELS.md](guide/CLUSTER-CHANNELS.md)):

- **файловый (pull)** — нода выкладывает разделы в `cluster/`, соседи забирают
  кроном. Несёт все данные и все объявления. Обязан работать;
- **Web API (push)** — только «сделай сейчас» (`nudge`, демо). Отказ = задержка.

Раздел проходит четыре шага, и у каждого своя функция:

| Шаг | Функция | Где |
|---|---|---|
| выложить свой | `publish_<раздел>` / `publish_cluster_<раздел>` | `lib/publish.sh`, `lib/cluster.sh`, модуль темы |
| забрать чужой | `peer_pull` по списку `CLUSTER_SYNC_SECTIONS` | `lib/cluster.sh` |
| проверить форму | `_peer_section_filter` (ключевое поле — имя или токен) | `lib/cluster.sh` |
| применить | `cluster_apply_<раздел>` | `lib/cluster.sh`, модуль темы |

**Новый раздел** = `publish_*` + имя в `CLUSTER_SYNC_SECTIONS` + ветка в
`_peer_section_filter`, если в разделе есть имена или токены + `cluster_apply_*`
в `cluster_sync` + метка в `_section_label`. Данные пира — недоверенные: форма
проверяется и на входе, и у стока.

Слияние — last-write-wins по `ts`. У дельты по метке времени обязан быть
напарник, сверяющий **факт** (правило 7, [guide/CLUSTER-SCOPE.md](guide/CLUSTER-SCOPE.md)):
что не применилось с первого раза, по одной метке не применится никогда.

Что из настроек общее для кластера, а что своё у ноды —
[guide/CLUSTER-SCOPE.md](guide/CLUSTER-SCOPE.md).

## 5. Жизнь профиля

```
завести     db_add_user -> sub_refresh <профиль>
                             ├─ proto_sync_users          ядра узнают нового
                             ├─ regen_user_subscription   файл(ы) sub/<token>
                             ├─ write_slotpass_db         пароли слотов
                             └─ sub_refresh_bg            фон: манифест, все подписки, заголовки
отключить   disable_user     users.db -> disabled.dat, кик, sub_refresh <профиль>
удалить     delete_user      чистка файлов + tombstone в cluster_state -> соседи удалят у себя
срок вышел  check_expired_users -> disable_user либо freeplan_enter
```

- Пароль профиля на каждой ноде **свой**; подписка склеивает ключи всех нод из
  манифестов пиров. Ключи доп. протоколов производны от пароля
  (`proto_uuid`, `proto_upsk`).
- `sub_refresh` без аргумента — полный перевыпуск (десятки секунд). С именем —
  быстрый путь для правки одного профиля. Правка касается всех (шаблон
  подписи, набор протоколов) — полный.
- Лимит устройств: [guide/DEVICE-LIMITS.md](guide/DEVICE-LIMITS.md); слоты и
  доп. ссылки: [guide/SLOTS.md](guide/SLOTS.md).

## 6. Web API и надстройка

Демон `webapi/hy2-webapi.py` (python3 stdlib, слушает loopback, наружу — через
`handle_path /api/*` в Caddy). Чтение — напрямую из файлов `DATA_DIR`
(`wa_core.py`, `wa_users.py`); **любая мутация** — запуск `webapi/dispatch.sh
<команда>`, который сорсит те же `lib/*.sh`. Значит правка функции в `lib/`
меняет и меню, и бот, и API разом.

Надстройка (кабинет клиента, отдельный приватный репозиторий) ходит **только**
в это API по HTTP — к файлам менеджера и к его скриптам она не обращается.
Контракт — [guide/API.md](guide/API.md). Меняешь ответ ручки — это правка
контракта: надстройка обновляется отдельно и позже.

После правки `webapi/` — `systemctl restart hy2-webapi`. Демон бота держит код
с момента запуска: правка `lib/` до него доезжает только после рестарта
([P-141](issues/OPS.md#p-141)).

## 7. Навигация по длинным модулям

Номера строк плывут — ищи по заголовку раздела (`grep -n '^# ----' lib/<модуль>.sh`).

| Модуль | Разделы по порядку |
|---|---|
| `lib/protocols.sh` | параметры узла → деривация кредов → установка движков → TLS → генерация конфигов → юниты → применение (рестарт только при изменении; TUIC с отсрочкой; Xray на горячую) → ссылки подписки → включение/выключение → учёт трафика → активность → онлайн → кик → состояние для кластера → самопроверка |
| `lib/cluster.sh` | реестр пиров → `peer_pull` → крючки → просьба обновиться → здоровье пиров → `cluster_sync` → ростер и состояние → сброс ключей → забыть адреса → забвение → применение состояния/ростера → оформление, срок, лимиты, привязки Telegram → `cluster_online_sync` |
| `lib/sub_links.sh` | релей → ссылки и токены → слоты → манифест → подписка одного профиля → полный перевыпуск → `sub_refresh` → заголовки подписки |
| `lib/perf.sh` | чтение и правка `config.yaml` → шейпинг tc → фолбэк nft/iptables → тарифные классы |

## 8. Как проверять правку

- **Тесты:** `bash tests/test-<тема>.sh`, каждый — самостоятельный скрипт.
  Песочница: `export HY2M_DATA_DIR=$(mktemp -d)` и `HY2M_WEBROOT` до `source
  lib/config.sh`; сеть и `systemctl` подменяются функциями. Весь набор:
  `for t in tests/test-*.sh; do bash "$t" || echo "FAIL $t"; done`.
- Проверка и её обработчик — одна команда: `[ … ] || { echo FAIL; exit 1; }`.
  Тест с необъявленной `fail` годами «проходил» ([P-187](issues/OPS-CLOSED-2.md#p-187)).
- **Читающие команды на проде безопасны:** `--health`, `cluster_health_report`,
  чтение `DATA_DIR`. Всё, что пишет (сбор, синхронизация, перевыпуск), — только
  в песочнице или дождавшись крона.
- **Отладка с `bash -x`** — только в песочнице: трассировка с боевыми данными
  кладёт адреса клиентов в `error.log` ([P-180](issues/OPS-CLOSED-2.md#p-180)).
- После правки смотри `/var/log/hy2-manager/error.log`: туда уходит stderr всех
  режимов.

## 9. Чек-лист изменения

1. Документ темы прочитан; записи реестра по теме просмотрены.
2. Есть ли уже функция, делающая это? (`grep` по `lib/`.) Вторая копия —
   будущая запись в реестре ([P-185](issues/CLUSTER.md#p-185)).
3. Как это на соседней ноде и на ноде со старой версией?
4. Цикл по юзерам? Посчитай форки.
5. Данные от пира или от клиента? Форма проверена у входа и у стока.
6. Тест рядом с правкой; весь набор зелёный.
7. `VERSION`: третье число +1 на коммит с кодом; коммит только с `docs/` версию
   не двигает.
8. Новая функция — документ в `guide/` и строка в его таблице. Найденная
   проблема — запись в `issues/`, даже если не чинишь.
9. В `docs/` публичного репозитория — без хостов, адресов и имён клиентов.
10. Ни один текстовый файл документации не длиннее 500 строк: разросся — режь
    по темам и оставляй указатель.
