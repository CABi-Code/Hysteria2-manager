# 01. Постановка задачи

## Что есть сейчас

Кластеризация (`lib/cluster.sh`) построена на общем секрете:

```bash
cluster_call() {   # host path [timeout]
    secret=$(cluster_secret)
    curl -fsS -H "X-Cluster-Auth: $secret" "https://${host}${path}"
}
```

Доверие бинарное. Знаешь секрет — ты внутри: читаешь манифесты ключей,
статистику, роутеры, IP-адреса и лимиты юзеров всех нод. Не знаешь — ты снаружи.
Середины нет.

Аутентификация юзера — `auth.type: command`, скрипт ищет юзера в локальном
`users.db`. Подписка (`lib/sub_links.sh`) собирает ключи со всех пиров, чтобы
любая нода отдавала объединённый список локаций. Для этого ноде нужно знать
чужих юзеров.

Модель предполагает, что все ноды принадлежат одному владельцу. Это верное
предположение для сегодняшнего кластера и неверное для маркета.

## Чего хотим

1. У юзера широкий выбор локаций от **разных владельцев**.
2. Владелец сервера управляет **только своими** юзерами.
3. Ноды обмениваются данными, **не доверяя друг другу**.
4. Вход **открытый**: любой поднимает сервер и продаёт мощность, без разрешения.
5. Расчёты **автоматические**, без арбитра.

Пункты 1–3 — это про полномочия. Пункты 4–5 — про деньги. Это две разные задачи,
и их важно не смешивать: первая решается подписями, вторая — предоплатой.

## Почему блокчейн не отвечает на главный вопрос

Блокчейн решает одну задачу: договориться о **порядке событий** между взаимно
недоверяющими сторонами без арбитра. Стоит дорого — репликация, консенсус,
финальность, публичность.

Задача «нода не доверяет ноде, но обслуживает её юзеров» — это не про порядок
событий. Это про **доказательство полномочия**: предъявить «этому юзеру
разрешено», не давая проверяющему власти над юзером. Подпись, а не консенсус.
Общая тетрадь тут не только не нужна, но и вредна: чем меньше ноды знают друг о
друге, тем ближе мы к цели.

Отдельно: **данные юзеров в цепи — это катастрофа.** Публичный неизменяемый
реестр «кто у кого купил VPN» уничтожает продукт, ради которого всё затевается.
Заметь иронию — приватность здесь аргумент *против* шаринга состояния.

Где цепь всё-таки оправдана:

* **Расчёты между незнакомцами.** Escrow вместо «он попользовался и пропал».
* **Sybil-стойкость через стейк** — если она вообще понадобится (см. 03,
  выясняется, что при правильной экономике почти нет).
* **Слэшинг.** Упирается в оракула, см. `04-attacks.md`.

Всё остальное — реестр нод, цены, локации — прекрасно живёт подписанным
gossip-файлом, который у тебя уже почти есть (`publish_peers_list`).

## Аналогия, которую стоит держать перед глазами

Роуминг GSM, сорок лет в проде без всякой цепи:

| GSM | Наш маркет |
|---|---|
| Домашний оператор (HLR) | Издатель |
| Гостевая сеть (VLR) | Оператор ноды |
| Абонент не отдаёт ключ гостевой сети | Ваучер не даёт власти над юзером |
| Гостевая выставляет счёт домашней, не абоненту | Оператор биллит издателя |
| Роуминговое соглашение | Открытый канал с депозитом |

Главное отличие: в GSM соглашения подписывают юристы между известными
компаниями. У нас участники анонимны — вот эту дельту и закрывает крипта, и
только её.
