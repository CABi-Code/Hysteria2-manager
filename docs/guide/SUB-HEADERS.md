# Оформление подписки: что клиент показывает поверх ключей

Ответ на `/sub/<token>` — не только список ключей. Современные клиенты
(Happ, v2RayTun, Hiddify, Streisand и другие на Xray/sing-box) читают из этого
же ответа **заголовки**: название профиля, строку расхода и срока, текст анонса,
кнопки ссылок. Через них нода объясняет человеку, что у него за доступ, сколько
от него осталось и куда идти дальше, — прямо в том приложении, которым он
пользуется, без бота и без мини-аппа.

Код: `lib/node.sh` (настройки, плейсхолдеры, факты плана), `lib/sub_links.sh`
(сборка персональных заголовков), `lib/caddy.sh` (общие заголовки в Caddyfile),
`lib/ui_subscription.sh` (меню «Оформление подписки»).

## Что нода отдаёт сейчас

| Заголовок | Значение | Персональный? |
|---|---|:--:|
| `profile-title` | название профиля (`SUB_TITLE`), base64 | да, если в шаблоне есть плейсхолдеры |
| `subscription-userinfo` | `upload=0; download=<расход>; total=<лимит>; expire=<ts>` | **да** |
| `announce` | текст под план юзера (демо / бесплатный / платный), base64 | **да** |
| `profile-update-interval` | как часто клиент обновляет подписку, часы (`SUB_UPDATE_HOURS`) | нет |
| `support-url` | кнопка «поддержка» (`SUB_SUPPORT_URL`) | нет |
| `profile-web-page-url` | кнопка «страница подписки» (`SUB_PAGE_URL`) | нет |
| `announce-url` | куда ведёт клик по анонсу (`SUB_ANN_URL`) | нет |
| любые прочие | свободный список `SUB_HEADERS` | нет |

Все настройки, кроме метки ноды, — **общие для кластера** (`SETTING_KEYS`,
last-write-wins, см. [CLUSTER-SCOPE.md](CLUSTER-SCOPE.md)): человек видит одно и
то же, к какой ноде бы ни подключился.

## Как заголовок становится персональным

`/sub/*` раздаёт **статику**, её отдаёт сам Caddy — нашего кода в запросе нет,
и привязать заголовок к юзеру напрямую нечем. Поэтому `write_sub_titles`
раскладывает «токен → значение» в `map {path}` и пишет сниппет, который
Caddyfile импортирует:

```
map {path} {sub_info} {
    /sub/<токен-юзера-А> "upload=0; download=1048576; total=0; expire=1790000000"
    /sub/<токен-юзера-Б> "upload=0; download=524288000; total=524288000"
    default "upload=0; download=0; total=0"
}
header subscription-userinfo "{sub_info}"
```

Следствия, которые надо помнить:

* **Сниппет живёт в конфиге Caddy.** Изменилось значение — нужен `reload`.
  Поэтому расход округляется вниз до мегабайта: подключённый, но молчащий клиент
  набирает килобайты и без округления дёргал бы reload на каждой прогонке.
* **Свежесть — до 5 минут.** Трафик и сроки НЕ входят в подпись входов подписки
  (`_subs_inputs_changed`, см. [CRON.md](CRON.md)) — иначе минутный
  `--online-sync` перевыпускал бы подписки постоянно. Заголовки обновляет
  безусловный перевыпуск в `--cluster-sync` (раз в 5 мин) и любое действие,
  дёргающее `sub_refresh`. Клиент всё равно перечитывает подписку раз в
  `profile-update-interval`, так что задержка не видна.
* **Название профиля без плейсхолдеров** остаётся одним статическим заголовком —
  map не строится вовсе.
* Значение заголовка с не-ASCII (русский текст, эмодзи) отдаётся как
  `base64:<...>` — так его принимают и Happ, и v2RayTun. Сырой UTF-8 в заголовке
  HTTP недопустим.

## Анонс: описание демо и информация о тарифе

У каждого плана свой текст, потому что и говорить им надо разное:

| План | Как определяется | Настройка | Текст по умолчанию |
|---|---|---|---|
| демо | строка в `DEMOS_DB` (`demo_row`) | `SUB_ANN_DEMO` | сколько трафика и времени осталось + «пока действует, оформите бесплатный или платный» |
| бесплатный | строка в `FREEPLAN_FILE` (`freeplan_has`) | `SUB_ANN_FREE` | израсходовано из недельной квоты + предложение платного |
| платный | всё остальное | `SUB_ANN_PAID` | срок, остаток, устройства, расход (без срока — свой текст) |

* Значение **`-`** — не показывать анонс этому плану. Пустая настройка = текст по
  умолчанию (он на русском и сразу осмысленный, отдельной настройки не требует).
* Клиенты показывают ~200 символов, дальше обрезают.
* Цифры берутся из **тех же данных, по которым доступ реально отбирают**
  (`user_plan_facts`): демо-строка, база недельного окна бесплатного тарифа,
  `expiry.dat` платного. Иначе клиент обещал бы одно, а нода делала другое.

### Плейсхолдеры

Работают и в тексте анонса, и в названии профиля (`SUB_TITLE`).

| Плейсхолдер | Что подставляется |
|---|---|
| `{user}` `{label}` `{name}` `{online}` | имя юзера, метка ноды, имя ноды, онлайн ноды |
| `{plan}` | `демо` / `бесплатный` / `платный` |
| `{expire}` | дата конца доступа (`дд.мм.гггг`) или «без срока» |
| `{left}` | сколько осталось: `43 мин` / `7 ч` / `12 дн` / `истёк` / `бессрочно` |
| `{used}` `{total}` | израсходовано / лимит трафика (`3.0G`, «без лимита») |
| `{devices}` `{rate}` | лимит устройств, персональный тариф скорости |

Плановые плейсхолдеры считаются **лениво**: шаблон без них не платит ни одним
лишним чтением файлов. Факты плана кэшируются на процесс — за один перевыпуск
подписок они нужны трижды (название, `subscription-userinfo`, анонс).

## Свободный список `SUB_HEADERS`

Отдельная настройка на каждый параметр клиента бессмысленна: у одного Happ их
шестой десяток, и список растёт быстрее менеджера. Поэтому есть строка вида

```
update-always: true|subscriptions-sort-type: ping|subscription-pin: true
```

— «имя: значение», разделитель `|`. Всё, что в ней, уходит в блок `/sub/*` как
заголовки. Имя фильтруется до `[A-Za-z0-9-]`, из значения вырезаются кавычки,
слэши и переводы строк (иначе развалился бы Caddyfile).

## Что вообще понимают клиенты

Проверено по документации приложений (август 2026).

**Понимают почти все:** `profile-title`, `subscription-userinfo`,
`profile-update-interval`, `announce`.

**v2RayTun** — плюс `announce-url`, `update-always`, `network-filter`
(показывать конфиг только на мобильной сети / только на Wi-Fi по имени),
`routing` (base64-профиль маршрутизации, перекрывает настройки приложения).
Значение с не-ASCII — с префиксом `base64:`.

**Happ** — самый богатый набор. Стандартные (работают всем):
`support-url`, `profile-web-page-url`, `routing-enable`, `custom-tunnel-config`,
`socks-auth-*`, `http-auth-*`. Расширенные — **требуют Provider ID** (регистрация
на стороне разработчика приложения, передаётся заголовком `providerid`): смена
URL и домена подписки (`new-url`, `new-domain`, `fallback-url`), крупные плашки
и системное «подписка истекает» (`sub-info-text`, `sub-info-button-*`,
`sub-expire`, `sub-expire-button-link`), напоминания об истечении
(`notification-subs-expire`), автоподключение и автопинг, фрагментация и шумы,
mux, TUN/proxy-режим, per-app proxy, темы, `subscription-pin`,
`subscriptions-sort-type`, `hide-vpn-icon` и прочее. Полный список — в
документации приложения; ставятся они через `SUB_HEADERS`, кода менеджера не
требуют.

**Описание сервера отдельной строкой** (`#title?serverDescription=<base64>` в
самом URI ключа) Happ тоже умеет — это подпись под именем сервера. Сейчас не
используется: подпись ключа собирает `SUB_TAG_TMPL`, и вторая строка под ней
пока не понадобилась.

Чего в заголовках **нет ни у кого**: баланса в деньгах, названия тарифа, кнопки
оплаты. Название тарифа per-user нода вообще не хранит (см. «Как дополнять»).

## Как дополнять

* **Новый параметр клиента** — не код, а `SUB_HEADERS` (меню → Подписка →
  Оформление → «Доп. заголовки»). Отдельную настройку заводить только тому, что
  надо считать per-user или показывать в TUI.
* **Новый персональный заголовок** — считаем значение из `user_plan_facts`,
  добавляем map в `write_sub_titles` рядом с существующими и строку в тест.
  Помни про цену reload: значение, меняющееся каждую минуту, туда не годится.
* **Новый плейсхолдер** — в `plan_apply_ph` плюс перечисление в `_plan_has_ph`
  (иначе он не считается персональным и название профиля останется статическим).
* **Название тарифа в анонсе** потребует хранить его per-user: сейчас нода знает
  только срок, устройства, скорость и признак бесплатного/демо. Пока обходимся
  `{plan}` — тип доступа, а не имя тарифа.
