# Модули бота: продажа, уведомления, админ-панель

Бот собран из трёх частей, включаемых по отдельности. Зачем: менеджер продаёт
доступ из коробки, но там, где сверху стоит своя витрина (мини-апп, кабинет,
чужая CRM), вторая точка продажи мешает — а уведомления и админ-панель нужны
по-прежнему. Архитектурная рамка — [SALES.md](SALES.md),
исходная проблема — [P-09](../issues/BILLING.md#p-09).

## Как включать

TUI: **Настройки → Telegram-бот → 11. Модули бота** — пункт переключает по
одному модулю и показывает текущее состояние.

Файл: `$DATA_DIR/bot.conf`, ключ `BOT_MODULES` — список через запятую.

```
BOT_MODULES=notify,admin      # бот не продаёт, но уведомляет и слушается админа
BOT_MODULES=none              # выключены все три
# ключа нет                   → включены все три (поведение по умолчанию)
```

Отсутствие ключа и пустое значение означают «включено всё» — поэтому «выключено
всё» записывается явным `none`. Демон читает `bot.conf` на каждом обращении:
рестарт не нужен (меню всё равно перезапускает бота для верности).

## Что даёт каждый модуль

| Модуль | Включён | Выключен |
|---|---|---|
| `sales` | витрина `/buy`, кнопка «Купить/продлить», счета Stars / провайдер BotFather / ЮMoney, выдача доступа по оплате | кнопки нет, `/buy` отвечает отказом, `buy:*` из старых сообщений игнорируется, `pre_checkout` тарифного счёта отклоняется (деньги не списываются), в уведомлениях не упоминается `/buy` |
| `notify` | напоминания об истечении срока, события бесплатного тарифа, карточка активации, алерты админам | бот молчит; срок, автоотключение и лимиты продолжают работать |
| `admin` | админ-панель, `/users`, `/add`, `/code`, `/status_srv`, `/refund` | админов у бота нет: `bot_is_admin` отвечает «нет» всем, админ видит клиентское меню |

## Что не выключается

Ядро — то, на чём держится надстройка над менеджером:

- привязка аккаунта (`/start КОД`, `/code`);
- приём пополнений мини-аппа (payload `topup:<tg_id>`): счёт минтит надстройка,
  но `successful_payment` приходит демону бота — long polling у него, второго
  владельца токена быть не может;
- делегирование `/start` мини-аппу (`MINIAPP_API`, см. [BOT-START.md](BOT-START.md)).

Правило для новых частей бота: **если это ломает надстройку — оно ядро, а не
модуль.**

## Где код

| Что | Где |
|---|---|
| `bot_mod_on`, `bot_sales_on`, гейт админа | `lib/tgbot.sh` |
| клавиатура клиента `bot_kb_client`, гейты покупки | `lib/tgbot_client.sh` |
| `pre_checkout`, кнопки, гейты уведомлений | `lib/tgbot_daemon.sh` |
| доставка уведомлений `notify_user` | `lib/notify.sh` |
| переключатель в TUI | `lib/tgbot_menu.sh` |
| проверка | `tests/test-bot-modules.sh` |

Новый модуль: имя в список `for x in sales notify admin` (меню и вывод статуса
в `lib/tgbot_menu.sh`), гейт `bot_mod_on <имя>` в точке входа своей части, строка
в таблицу выше и случай в тест.
