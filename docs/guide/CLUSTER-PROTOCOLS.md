# Состояние протоколов по кластеру

Каждая нода публикует снимок своих протоколов, остальные забирают его обычной
синхронизацией. Так с любой ноды видно, что где включено и что реально
слушает, — не заходя по SSH на каждый VPS.

## Зачем

Кластерная проверка здоровья (`peer_probe`, [PEER-HEALTH.md](PEER-HEALTH.md))
отвечает на один вопрос: отдаёт ли пир свои данные по HTTPS. Нода, у которой
лежит Hysteria или не поднялся Xray, по этому критерию совершенно здорова —
подписка с неё раздаётся, ключи мёртвого протокола в ней есть, и жалоба
приходит от клиента, а не от менеджера. Разбор такого случая — `docs/issues/`,
P-51.

## Формат

`proto_state_lines()` (`lib/protocols.sh`) — одна строка на протокол:

```
proto|enabled|up|port|l4
hy2|1|1|11478|udp
vless|1|1|8443|tcp
ss|0|0|8388|tcp
```

| Поле | Значение |
|---|---|
| `proto` | `hy2`, `vless`, `vlessx` (VLESS+XHTTP), `ss`, `trojan`, `tuic` |
| `enabled` | включён в настройках ноды; у `hy2` всегда `1` — это базовый протокол |
| `up` | сервис активен **и** порт слушается, то есть протокол принимает соединения |
| `port`, `l4` | порт и транспорт (`tcp`/`udp`) — по ним же строятся ключи подписки |

Порты снимаются одним вызовом `ss -ltnH`/`ss -lunH` на весь снимок (см. правила
против форков в [CRON.md](CRON.md)), состояние сервиса — `systemctl is-active`.

## Как ходит по кластеру

| Шаг | Код |
|---|---|
| публикация в `$WEBROOT/cluster/protocols` | `publish_cluster_protocols()` (`lib/cluster.sh`), зовётся из `cluster_sync` |
| раздача пирам | Caddy отдаёт весь `/cluster/*` по `X-Cluster-Auth` — отдельного маршрута не нужно |
| приём в кэш `peers/<нода>.protocols` | секция `protocols` в `CLUSTER_SYNC_SECTIONS` |
| чтение | `peer_protocols <нода>`, `cluster_protocols`, `cluster_proto_state <нода> <proto>` |

Свежесть данных — mtime файла кэша: он переписывается на каждом успешном
sync, а протухший mtime сам по себе означает «пир давно не отвечает».
Отдельного `ts` в файле нет намеренно — дублировать нечего.

`cluster_protocols` отдаёт сводку по всему кластеру строками
`нода|proto|enabled|up|port|l4|возраст_сек` (своя нода — возраст `0`,
снимается на месте). Пир без кэша в сводку не попадает: про него сказать
нечего, а строка «всё по нулям» читалась бы как «всё выключено».

## Где смотреть

Меню протоколов → пункт 8 «Протоколы по нодам кластера»
(`proto_cluster_screen`, `lib/ui_protocols.sh`): по строке на ноду,
💚 работает · 🔴 включён, но не слушает · ⚪ выключен, плюс возраст данных.

## Ограничение, о котором нельзя забывать

Состояние **локальное**. `up=1` значит «порт слушается на самой ноде» и ничего
не обещает про путь до клиента: порт может резать файрвол площадки или не
пробрасывать фронт/релей, на который указывает A-запись домена ноды. Ровно так
и выглядел P-51 — движок жив, снимок зелёный, клиент не подключается.

Внешней пробы портов пира тут нет сознательно: у TCP она стоила бы три строки,
но самые интересные протоколы (Hysteria, TUIC) живут на UDP, а молчание UDP
неотличимо от потери пакета — судить по нему нельзя. Проверка «доходит ли
снаружи» остаётся ручной: клиент нужного протокола с чужой ноды по ключу из
манифеста пира.

## Как дополнять

- **Новый протокол** → строка в `proto_state_lines()`. Больше нигде ничего
  менять не нужно: и синхронизация, и экран разбирают файл построчно.
- **Новый потребитель** (бот, Web API) → `cluster_protocols` или
  `cluster_proto_state`, не читайте `peers/*.protocols` сами.
- **Старая нода в кластере** секции `protocols` не публикует — у неё раздела
  просто нет, в сводке она не появится. Лечится обновлением ноды, не кодом.
