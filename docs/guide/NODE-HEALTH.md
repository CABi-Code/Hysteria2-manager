# Самодиагноз ноды и дозор кластера

> Закрывает [P-184](../issues/CLUSTER-CLOSED-2.md#p-184) и частично
> [P-32](../issues/CLUSTER.md#p-32). Связь с пиром как таковую («отвечает ли
> :443») проверяет [PEER-HEALTH](PEER-HEALTH.md); здесь — что у ноды внутри.

## Замысел

Сосед судил о ноде по одному признаку: отдаёт ли она `/cluster/manifest`. Нода
с упавшим ядром протокола, вставшим кроном или непродлённым сертификатом
отвечала исправно и считалась здоровой, пока не напишет клиент.

Теперь нода **сама пишет о себе короткую справку** и выкладывает её в файловый
канал разделом `health`. Соседи забирают раздел вместе с остальными и разбирают
в беды. Три следствия:

- упавшее внутри ноды видно с любой другой ноды, без захода на неё;
- вставший крон виден по самому молчанию: справка перестаёт обновляться;
- пороги применяет **читатель**, а не автор справки — их можно поменять на одной
  ноде, не дожидаясь обновления остальных.

Почему файловый канал, а не запрос «как дела?» в Web API соседа: справка обязана
доехать и с ноды без Web API (критерий выбора канала —
[CLUSTER-CHANNELS](CLUSTER-CHANNELS.md)).

## Справка

`health_self` (`lib/health.sh`) печатает строки `ключ=значение`. Только факты:

| Ключ | Значение | Откуда |
|---|---|---|
| `ts` | когда посчитана | — |
| `ver` | версия менеджера | `VERSION` |
| `down` | метки неработающих юнитов через запятую | `health_units` + `systemctl is-active` |
| `cron` | `режим:секунд_с_финиша`, три режима | отметки `cron_done` |
| `cert_days` | дней до конца сертификата домена; `none` — доверенного нет | сертификат Caddy, раз в час |
| `disk` | занято на `/`, % | `df` |
| `healed` | `метка@ts` последнего самолечения | `health_heal` |

**Какие юниты обязаны работать** — список живой (`health_units`): Hysteria
всегда, Caddy при настроенной подписке, Xray и sing-box по включённым
протоколам, Web API и бот — если включены. Выключенный протокол бедой не
считается. Тем же списком пользуется старт меню, решая, нужна ли пересборка
протоколов.

**Отметка финиша крона.** Замок режима (`.<режим>.lock`) говорит о старте.
Зависший или упавший на полпути прогон от здорового отличает только финиш,
поэтому ветки `--online-sync`, `--cluster-sync` и `--collect` последней строкой
зовут `cron_done <режим>` (файл `.<режим>.done`). Отметки ещё нет — возраст
считается нулевым: о том, чего не знаем, не тревожим.

## Разбор в беды

`health_problems` читает справку и печатает `код<TAB>текст`. Код стабилен от
такта к такту — по нему дозор подтверждает беду; текст для человека.

| Код | Условие | Порог |
|---|---|---|
| `stale` | справка пира не обновлялась | `HEALTH_STALE_SEC` = 15 мин |
| `svc:<метка>` | юнит из `down` | — |
| `cron:<режим>` | режим давно не доходил до конца | online-sync 15 мин, cluster-sync 25 мин, collect 90 мин |
| `cert` | сертификата нет или осталось мало | `HEALTH_CERT_MIN_DAYS` = 14 (Caddy продлевает за 30) |
| `disk` | диск почти полон | `HEALTH_DISK_MAX_PCT` = 90 |

Устаревшая справка даёт одну беду `stale` — остальное в ней устарело вместе с
ней. Своя справка на свежесть не проверяется: она считается в момент показа,
чтобы меню видело упавший юнит сразу, а не через такт.

## Самолечение

`health_heal` зовётся перед записью справки, раз в такт `--online-sync`.

| Что | Когда | Потолок |
|---|---|---|
| поднять юнит (`reset-failed` + `start`) | юнит в состоянии **failed** | раз в 10 мин на юнит |
| перезапустить Caddy ради нового выпуска сертификата | доверенного сертификата нет **и** запрос к своему домену падает на проверке цепочки | раз в час |

Юнит, остановленный рукой (`inactive`), не трогается: админ мог остановить его
намеренно. Каждое лечение пишется в `error.log` и в `healed=` справки — молча
оно не проходит. Перезапуск Caddy на живом случае не проверен (такой ноды в
кластере сейчас нет), судья — код 60 у `curl`, а не эвристика по файлам.

## Где это видно

| Где | Как |
|---|---|
| шапка главного меню | «🔴 Неполадок в кластере: N» и построчная расшифровка |
| `hy2-manager.sh --health` | та же расшифровка в stdout, полсекунды; код 0 — чисто, 1 — есть беды |
| суточный отчёт | через `cluster_health_report` ([DAILY-REPORT](DAILY-REPORT.md)) |
| Telegram админам | `--watch`, см. ниже |

Все читатели идут через `cluster_health_report` (`lib/cluster.sh`): связь с
пирами + справки + недостача профилей. Новый потребитель зовёт её же, а не
разбирает файлы сам.

## Дозор: живое сообщение админам

`--watch` печатает первой строкой ключ (`watch:<начало>`), дальше HTML. Пусто —
сказать нечего. Доставка — как у [пробы из РФ](RU-PROBE.md): крон оператора с
пайпом в команду, которая **правит сообщение по ключу**, а не шлёт новое.

```
*/5 * * * * o=$(/path/hy2-manager.sh --watch 2>/dev/null) && [ -n "$o" ] && echo "$o" | <команда доставки>
```

В строке крона нельзя `%`. Дозор нужен на одной ноде кластера.

- Беда объявляется со **второго такта подряд**: одиночный провал пробы или
  перезапуск юнита посреди обновления сообщения не стоят.
- Одно сообщение на инцидент; оно правится каждый такт, закрывается тем же
  ключом («✅ … снова в порядке, было с … по …») и повторяет итог
  `HEALTH_TAIL_SEC` (15 мин) на случай сорванной доставки.
- Общая функция инцидента — `incident_message` (`lib/health.sh`); проба из РФ
  на неё пока не переведена ([P-186](../issues/OPS.md#p-186)).

## Данные

| Файл | Формат | Срок |
|---|---|---|
| `health.dat` | справка о себе, `ключ=значение` | перезаписывается каждый такт |
| `peers/<имя>.health` | справка пира | перезаписывается при заборе |
| `.<режим>.done` | пустой, время правки = финиш режима | постоянно |
| `.health_cert` | дней до конца сертификата или `none` | час |
| `.heal.<метка>`, `.health_healed` | время и след последнего лечения | постоянно |
| `watch_keys.dat` | коды бед прошлого такта | такт |
| `watch_episode` | `начало\|закрытие` инцидента | до следующего |

Данных о клиентах нет ни в одном файле.

## Безопасность

**Что трогает:** голос сервиса (сообщения админам), запуск юнитов на своей
ноде. Доступ, деньги и данные клиентов — нет.

| Угроза | Ответ |
|---|---|
| Скомпрометированная нода врёт в справке | Худшее — ложная тревога или ложное «всё хорошо» про саму себя. Справка ничего не меняет у читателя: по ней не запускается ни одно действие, только текст |
| Разметка или команды в справке пира | Значения проходят по форме (`down` — `[a-z0-9,]`, числа — числа), остальное не читается; в сообщение текст идёт через `tg_esc` |
| Лечение как рычаг: заставить ноду дёргать юниты | Лечение запускается только по состоянию **своей** ноды, чужая справка его не вызывает; потолки по частоте |
| Справка раскрывает устройство ноды | Раздел отдаётся только по секрету кластера, как остальные; имён клиентов и адресов в нём нет |
| Спам админу | Одно живое сообщение на инцидент, объявление со второго такта |

## Потолки

- **Тревогу шлёт та нода, где настроена доставка.** Лежит она — молчат все.
- **Беда внутри ноды без кластера видна только в её меню** и `--health`.
- **Дозор не различает наблюдателей.** Кворума «не видят минимум двое» нет —
  он описан в [design/PEER-WATCH](../design/PEER-WATCH/README.md) и нужен, когда
  нод станет больше трёх.
