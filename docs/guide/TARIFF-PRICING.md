# Цена тарифа: где живёт и как считается в звёздах

Цена — часть каталога, а каталог у менеджера. Витрина бота, счёт на оплату и
`GET /v1/tariffs` берут одну и ту же цену из `tariffs.conf`; внешним кабинетам
пересчитывать её не нужно и нельзя — иначе клиент увидит одно, а заплатит
другое. Рамка решения — [SALES.md](SALES.md),
проблема-предок — [P-09](../issues/BILLING.md#p-09).

## Где цена

`$DATA_DIR/tariffs.conf`, строка `код|название|дни|устройства|цены|валюты|опции`.
Цены и валюты — `/`-списки одинаковой длины: `299/240|XTR/RUB` — один тариф с
ценой в звёздах и в рублях. `XTR` = Telegram Stars (цена = число звёзд), прочее
— валюта платёжного провайдера в основных единицах.

Правит их TUI: **Настройки → Telegram-бот → 4. Тарифы**.

## Два режима звёздной цены

`bot.conf`, пункт меню **Тарифы → 6. Цена в звёздах**:

| Ключ | Значения | Смысл |
|---|---|---|
| `STARS_MODE` | `fixed` (по умолчанию) \| `rate` | откуда берётся цена в XTR |
| `STARS_RUB_PER_STAR` | число > 0 (напр. `1.5`) | курс для режима `rate` |

- **fixed** — цена XTR берётся из строки тарифа как есть. Тариф без колонки XTR
  за звёзды не продаётся.
- **rate** — `XTR = ceil(цена в RUB / STARS_RUB_PER_STAR)`. Колонка XTR в файле
  игнорируется, её можно не заполнять: звёздная цена появится сама. Тариф без
  рублёвой цены не меняется — считать не из чего.

Округление **вверх**: звёзды целые, а недобор — это продажа дешевле цены.
Мусорный или нулевой курс трактуется как `1` (делить на ноль в витрине нельзя).

Курс **пополнения баланса** мини-аппа сюда не относится: пополнение — не тариф,
это деньги надстройки и её курс.

## Где код

| Что | Где |
|---|---|
| режим, курс, пересчёт `tariff_prices_effective` | `lib/tariffs.sh` |
| витрина, меню валют, счёт | `lib/tgbot_client.sh` |
| список тарифов админу в боте | `lib/tgbot_daemon.sh` |
| список и переключатель режима в TUI | `lib/tgbot_menu.sh` |
| та же формула для API + блок `pricing` | `webapi/wa_dispatch.py` |
| проверка (бот и API считают одинаково) | `tests/test-stars-price.sh` |

Новая валюта или новый способ считать цену — **одна** правка
`tariff_prices_effective` и её питонового двойника `_apply_stars_mode`; всё
остальное зовёт их. Считать цену в третьем месте нельзя: тест
`test-stars-price.sh` сверяет bash и python именно поэтому.
