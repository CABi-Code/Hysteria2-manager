# Российские сервисы: на ноде отрезаны, у клиента мимо VPN

Код: `lib/rublock.sh` (всё), точки вызова — `proto_write_xray_config` /
`proto_write_singbox_config` / `proto_sync_users` (`lib/protocols.sh`),
`write_sub_titles` (`lib/sub_links.sh`), `cluster_sync` (`lib/cluster.sh`).
Тест: `tests/test-rublock.sh`.

## Зачем

Российские приложения (банки, маркетплейсы, соцсети, мессенджеры) определяют,
что пользователь пришёл через VPN, и узнают **IP сервера**, с которого пришло
соединение. Этот адрес сдают, и его блокируют на срок до нескольких недель: нода
пропадает для всех клиентов в стране.

Сдать можно только тот адрес, который приложение **увидело**. Значит, нода не
должна соединять клиента с российскими сервисами вообще.

## Два слоя из одного списка

Что считается российским, задано в одном месте, в начале `lib/rublock.sh`:
`geosite:category-ru`, домены `.ru`, `.su`, `.рф` и `geoip:ru`. Оба слоя
собираются из этого списка.

| Слой | Что делает | Если не сработал |
|---|---|---|
| **Сервер** | все движки отбивают соединения к РФ-доменам и РФ-IP | — это последняя линия: адрес ноды российский сервис не увидит |
| **Подписка** | клиент получает профиль маршрутизации «РФ напрямую», и российские сервисы у человека работают через его обычный интернет | российское приложение через VPN не откроется (ошибка соединения), но адрес не утечёт |

Серверный слой — гарантия, клиентский — удобство. Поэтому блокировка на сервере
не зависит от того, применил ли клиент профиль.

### Сервер: по движку

| Движок | Протоколы | Как |
|---|---|---|
| Xray | VLESS, VLESS-X, SS-2022, Trojan | outbound `blackhole` + два правила в `routing`: домены, потом IP |
| sing-box | TUIC | секция `route`: `sniff`, `reject` по суффиксам, `reject` по rule-set `.srs` |
| Hysteria | Hysteria 2 | блок `acl` в `config.yaml` между маркерами `# >>> hy2-manager rublock` |

Решения, которые выглядят странно:

* **Xray — `AsIs`, без резолва.** Клиент почти всегда присылает имя, а не адрес,
  и резолвить каждое имя ради проверки geoip (`IPIfNonMatch`) значило бы добавить
  задержку всему трафику. Имя ловит список доменов, сырой IP — geoip. Дыра:
  российский сервис на нероссийском домене, которого нет в `category-ru`.
* **Hysteria получает вырезку `.dat`, а не полные файлы.** Полные `geoip.dat` и
  `geosite.dat` (около 30 МБ) Hysteria разворачивает в память целиком: процесс
  вырастает с ~20 до ~250 МБ. Поэтому `_rublock_trim_dat` копирует из protobuf-списка
  только записи с нужным кодом (сотни КБ), и память остаётся около 30 МБ.
  Вырезка пересобирается, когда Xray обновил исходник.
* **sing-box — только rule-set.** Начиная с 1.12 он не читает `geoip.dat`.
  Файлы `.srs` скачиваются с GitHub SagerNet в каталог протоколов и обновляются
  раз в неделю. Если скачать не удалось, правило по rule-set не пишется, а суффиксы
  остаются: с несуществующим путём sing-box не стартовал бы вовсе.
* **Чужой `acl` в Hysteria не трогаем.** Если в конфиге уже есть ручной `acl:`,
  второй ключ сломал бы YAML. В этом случае блок не добавляется, и Hysteria
  остаётся без блокировки. Если ручной acl нужен, в него надо самому дописать
  правила из `_rublock_hysteria_block`.
* **Hysteria перезапускается, только если файл изменился.** Перезапуск рвёт все
  сессии, поэтому повторный apply обязан давать тот же файл байт в байт (это
  проверяет тест).

### Подписка: по клиенту

Оба клиента читают заголовок с одним именем `routing`, но формат у них разный.
Поэтому в блоке `/sub/*` значение выбирается по `User-Agent`:

| Клиент | `User-Agent` | Значение |
|---|---|---|
| Happ | `Happ/…` | `happ://routing/onadd/<base64 профиля>` — профиль добавляется и включается; при повторе с тем же `Name` перезаписывается |
| v2RayTun | `v2raytun/…` | base64 объекта маршрутизации Xray (формат экспорта приложения, direct = `freedom`) |
| остальные | — | ничего. В Hiddify есть встроенная настройка региона «Россия»: её человек включает сам |

Заголовки общие для всех юзеров и лежат в том же сниппете, что и персональные
(`write_sub_titles`). Сниппет перевыпускается кроном, поэтому изменения доезжают
до всех нод без перезаписи Caddyfile.

## Как применяется по кластеру

Конфиги Xray и sing-box пересобирает `proto_sync_users`, а его вызывают только
при смене юзеров. Поэтому после обновления кода или смены настройки блокировка
сама не включилась бы. `rublock_sync` в начале `cluster_sync` (раз в 5 минут)
дёшево проверяет, есть ли в конфигах след блокировки, и пересобирает их, только
если он расходится с настройкой. Для Hysteria конфиг сравнивается целиком.
Отдельного канала между нодами не нужно: каждая нода догоняет себя сама.

## Настройка

`RU_BLOCK=0` в `node.conf` выключает **серверный** слой на этой ноде: правила
уходят из движков в течение 5 минут. Настройка локальная для ноды (не входит в
`SETTING_KEYS`). Профили в подписке от неё не зависят: «российское напрямую»
полезно клиенту в любом случае.

## Чего это не закрывает

* **Факт VPN.** Android сообщает приложениям, что поднят VPN-интерфейс. Приложение
  может отказать в работе или пожаловаться, но адреса ноды не узнает.
* **Запрос приложения к нероссийскому сервису «узнать мой IP».** По адресу
  назначения он не российский, поэтому уйдёт через ноду и покажет её адрес. От
  этого защищает только исключение приложения из VPN целиком (per-app в
  настройках клиента), а передать список приложений через подписку нельзя.
* **Российский сервис вне `category-ru` и вне РФ-IP** (например, на зарубежном CDN).

## Как дополнять

* **Новый домен или категория** — переменные в начале `lib/rublock.sh`. Все слои
  собираются из них, отдельно ничего не правится.
* **Новый клиент с маршрутизацией из подписки** — матчер по `User-Agent` и строка
  в `rublock_sub_headers`, строка в таблицу выше и проверка в тест.
