# Суточный отчёт о сервисе

Раз в сутки — сводка по всему кластеру из двух частей: **клиенты и трафик** и
**техника**. Нужна, чтобы деградацию (ночные падения службы, рост сорванных
рукопожатий, отставшая по версии нода, лавина киков, истекающий сертификат)
видеть, не дожидаясь жалобы.

Техническая часть начинается с **сигналов**: 🔴 срочно — уже бьёт по клиентам
или ударит в ближайшие дни, 🟡 посмотреть — ухудшается, но терпит. Нет сигналов —
одна строка 💚. Ниже — подробности по каждой ноде, чтобы по сигналу сразу было
видно, где искать.

Код: `lib/report.sh`; точки вызова — `hy2-manager.sh` (`--online-sync`,
`--collect`, `--daily-report`); раздел `netday` — `CLUSTER_SYNC_SECTIONS` в
`lib/cluster.sh`. Тест — `tests/test-daily-report.sh`.

## Как устроено

Отчёт складывается из трёх источников, потому что ни у одной ноды нет всего:

| Что | Где считается | Как попадает в отчёт |
|---|---|---|
| профили по видам (оплачен / без срока / истёк / бесплатный / демо / отключён), «оплата кончается в 3 дня» | нода отчёта, `user_plan_facts` | профили кластерные, у любой ноды они те же |
| трафик, «пользовались», топ-3 | нода отчёта: кумулятивные счётчики **всех** нод (`self.stats` + `peers/*.stats`) минус снимок прошлого отчёта `report_base.dat` | разность по паре (нода, юзер) |
| скорость: средняя и медиана | нода отчёта: `report_sample` в каждом `--online-sync` пишет скорости спидометра всех нод (`rates.dat` + `peers/*.rates`) в `report_samples.dat` | статистика по выборкам |
| сеть и ресурсы: подключения, обрывы, ошибки, запуски, падения и текущее состояние служб, кики, сертификат, автообновление, LA/RAM/swap/диск | **каждая нода о себе** — `report_netday` по своим журналам | раздел кластера `netday`, публикуется в `--collect` (раз в 30 мин) |
| кластер: версии, недоступность за сутки, текущие проблемы | нода отчёта: `peers/*.version`, строки `cluster_health_report`, накопленные в выборках | — |

После печати отчёт делает новый снимок счётчиков и обнуляет выборки: следующий
отчёт считает ровно своё окно. Окно пишется в заголовке — запустили руками
дважды, второй покажет минуты, а не сутки.

### Решения, которые выглядят странно

* **Скорость — только «в работе».** В выборку идут юзеры со скоростью не ниже
  порога активности (`ACTIVITY_THRESHOLD_BPS`, тот же, что у `collect_activity`).
  Иначе медиану утопят нули keepalive-сессий спящих телефонов. Это скорость,
  которую клиенты реально получают, а не ёмкость канала.
* **«Пользовался» = больше 1 МБ за окно.** Меньше — фоновые проверки клиента.
* **Счётчик меньше снимка — его сбросили.** Тогда весь текущий счётчик считается
  трафиком окна, а не отрицательной разностью.
* **Выборки на ноде, где отчёт не печатают, не копятся:** снимок старше двух
  суток (`REPORT_MAX_AGE_SEC`) — всё начинается заново.
* **В выборках нет адресов и юзеров** — только нода и скорость. Юзеры есть в
  снимке трафика (`report_base.dat`): без них не посчитать топ.
* **Ошибки менеджера — только строки с датой** из `error.log`. Остальное там —
  stderr интерактивного меню без меток времени, к суткам его не привязать.

### Что значат строки сети

| Строка | Источник | Как читать |
|---|---|---|
| ушли по тишине | Hysteria `client disconnected` с `no recent network activity` | клиент пропал из сети без прощания: сон телефона, смена сети, **или обрыв по пути**. Рост при том же числе подключений — сигнал |
| закрыл сервер / клиент | `Application error (local/remote)` | кик, перезапуск движка / клиент сам отключился |
| до сайтов не достучались | `TCP/UDP error` с ошибкой dial/reset | сайт недоступен с ноды; к связи клиента с нодой не относится |
| отсечено правилами | `error: rejected` | блокировка РФ-сервисов ([RU-BLOCK.md](RU-BLOCK.md)) — норма |
| сорванные TLS-рукопожатия | Xray `TLS handshake error` | обрывы на входе TLS-протоколов; «по таймауту» — пакеты не дошли: сканеры или фильтрация по пути |
| запуски / падения служб | `Started` / `Failed with result` в журнале юнита | запуск бывает и плановым (обновление); падение — всегда разбирать |

### Сигналы

Пороги — переменные `REPORT_*` в начале `lib/report.sh`.

| Сигнал | Уровень | Откуда |
|---|---|---|
| служба включена, но не работает сейчас | 🔴 | `systemctl is-active` на ноде (`down`) |
| падение службы за сутки | 🔴 | `Failed with result` в журнале юнита |
| OOM, диск ≥ 90%, память ≥ 92% | 🔴 | ядро, `df`, `free` |
| сертификат ≤ 7 дн. | 🔴 | TLS на :443 ноды, как его видит клиент |
| нода недоступна сейчас | 🔴 | `cluster_health_report` |
| сертификат ≤ 20 дн. | 🟡 | автопродление должно было сработать за 30 |
| диск ≥ 75%, swap ≥ 50%, нагрузка выше числа ядер | 🟡 | |
| версия не как у ноды отчёта | 🟡 | `peers/*.version` |
| нода была недоступна в части проверок за сутки | 🟡 | выборки `D` |
| автообновление с ненулевым кодом, ошибки менеджера и Xray, ≥ 10 пропущенных тиков, ≥ 30 киков | 🟡 | `update.log`, `error.log`, журналы, `limit.log` |
| нет сетевых данных ноды или им больше часа | 🟡 | `peers/*.netday` |
| профиль не заведён у пира | 🟡 | `cluster_coverage_report` |

## Доставка

`--daily-report` печатает HTML для Telegram в stdout: сначала клиентскую часть,
затем строку из одного символа `\f`, затем техническую. Части рассчитаны на два
отдельных сообщения. Куда и каким ботом их слать, менеджер не знает: оператор
вешает крон на одну ноду кластера (любую, данные кластерные) с пайпом в свою
команду доставки, которая читает stdin и делит его по `\f`:

```
50 5 * * * /opt/hy2-manager/hy2-manager.sh --daily-report | <команда доставки>
```

Без доставки отчёт можно запустить руками и прочитать в терминале; снимок при
этом обновится.

## Как дополнять

* Новая цифра о **ноде** (её журналы, её службы) — ключ в `report_netday` и
  строка в `_report_net_block`; если по ней надо реагировать — правило в
  `_report_node_alerts`. Старые ноды ключа не пришлют — `n()` даст 0,
  поэтому показывать стоит то, где 0 не врёт, либо проверять наличие ключа.
* Новая цифра о **клиентах** — в `daily_report`, из данных, которые уже есть у
  каждой ноды. Нужна история внутри суток — выборка в `report_sample`, она
  обнуляется вместе с отчётом.
* Раздел `netday` — «справка», слияния нет: нода пишет только о себе.
