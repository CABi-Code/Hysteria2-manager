# Онлайн по активности трафика

## Зачем

Раньше «онлайн» в webapi (`user_payload.online`) и виджет «N соединений» в
вебаппе считались по **наличию соединений**: сумма Hysteria `/online` + Xray
`>>>online` + число TUIC-соединений sing-box. Клиент для замера латентности
пингует все протоколы сразу — каждый пинг регистрируется движком как
«соединение». Один юзер с одним реально работающим протоколом показывался как
«5+ соединений». Байтовой разницы между пингом и реальным трафиком online-API
движков не дают, поэтому отфильтровать пинги на уровне «есть сокет» нельзя.

Единственный устойчивый признак «реально пользуется, а не пингует» — **движение
байтовых счётчиков**: пинг/keepalive двигает их на единицы КБ за интервал
(десятки Б/с), реальное использование — на порядки больше.

## Алгоритм

Фоновый тред-демон `_online_sampler` в `webapi/hy2-webapi.py`:

1. Раз в `ONLINE_SAMPLE_SEC` (дефолт 15 с) снимает кумулятивный трафик всех
   юзеров через `_all_user_totals()` — один проход по `stats.dat` (локальный
   трафик) и по `peers/*.stats` (пировые кэши). Это те же источники, что
   `traffic` в `user_payload`, так что суммы сходятся. Все движки пишут в общий
   `stats.dat`, поэтому метрика протокол-агностична.
2. Для каждого юзера сравнивает текущий снимок с предыдущим (`_online_prev`):
   скорость `(cur - prev) / dt`. Если `>= ONLINE_RATE_BPS` (дефолт 2048 Б/с) —
   юзер попадает в `_online_active`. `delta < 0` = сброс счётчика (рестарт),
   игнорируется.
3. `is_online(user)` — членство в `_online_active` под `_online_lock`.

`user_payload.online` = `is_online(user)`. Первый снимок после старта демона
даёт baseline, активность считается со следующего тика (~15 с холодного старта
после рестарта webapi — редкое событие). Так как сэмплер независим от опросов,
`online` корректен уже на первой загрузке дашборда (вебапп не поллит).

`online_connections` (сырое число соединений, включая пинги) оставлено в payload
для совместимости API, но вебаппом больше не показывается.

## Пороги (env на юните демона)

- `HY2M_ONLINE_RATE_BPS` — порог скорости, Б/с. Дефолт `2048` (2 КБ/с): выше
  пинг-шума (сотни Б/с даже при частых пингах), ниже лёгкого сёрфинга.
- `HY2M_ONLINE_SAMPLE_SEC` — период сэмплирования, с. Дефолт `15`, минимум 5.

Идлящий, но подключённый юзер (только keepalive, без реального трафика) считается
**не в сети** — это соответствует смыслу «онлайн = реально пользуется».

## Файлы

- `webapi/hy2-webapi.py` — `_all_user_totals`, `_online_sampler`, `is_online`,
  константы `ONLINE_*`, запуск треда в `main()`, поле `online` в `user_payload`.
- `resources/js/pages/Dashboard.vue` (cibpn-webapp) — виджет «Онлайн» показывает
  статус «Онлайн / Не в сети» по `vpn.online`, а не счётчик соединений.
- `docs/API.md` — семантика полей `online` / `online_connections`.

## Зависимости

Только stdlib (`threading`, `time`) — как и весь демон. Состояние в памяти, без
файлов; на рестарте baseline пересобирается за один тик.

## Как дополнять

- **Другой порог/окно** — env-переменные выше, без правки кода.
- **Новый источник трафика** (ещё один per-user файл счётчиков) — добавить его
  разбор в `_all_user_totals()`; сэмплер и `is_online` менять не нужно.
- **«Активные устройства сейчас»** вместо boolean — если появится per-IP трафик
  в реальном времени, ту же дельта-логику применить к парам (user, ip).
