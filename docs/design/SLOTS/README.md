# Слоты: устройство = свой кред, а не адрес

Согласовано, кода нет. Цель — продавать **устройства**, а не адреса: чтобы
телефон, домашний ПК, ноутбук и родители считались за четыре устройства, даже
когда все они сидят за одним внешним адресом, и чтобы лимит **отказывал**, а не
дёргал.

Что ограничивает сегодня и почему этого мало — [../../guide/DEVICE-LIMITS.md](../../guide/DEVICE-LIMITS.md).
Продажа устройств в надстройке — `надстройка/docs/DEVICES.md`.

## 1. Зачем

Сегодня «устройство» = уникальный IP-адрес, а лимит держится киком раз в минуту.
Отсюда две дыры, и они противоположные:

* **Недосчёт.** Пять аппаратов за одним домашним Wi-Fi — один адрес, одно
  устройство. Ровно то, за что мы собираемся брать деньги, не считается вовсе.
* **Тряска.** Кик не сходится против автопереподключения: клиент возвращается
  за секунды, через минуту всё повторяется ([P-44](../../issues/LIMITS.md#p-44)).
  Юзер с лимитом ниже реального числа устройств живёт в постоянных обрывах, а
  лишнее устройство всё равно работает — урывками.

Слот закрывает обе: устройство опознаётся по **своему креду**, а не по адресу, и
занятый слот **не пускает** новое подключение вместо того, чтобы рвать старое.

## 2. Что измерено

Проверено на изолированных инстансах (Hysteria 2.9.2, Xray 26.3.27,
sing-box 1.13.14), подробные таблицы — [../../guide/DEVICE-LIMITS.md](../../guide/DEVICE-LIMITS.md) §5.

| Факт | Следствие для слотов |
|---|---|
| Auth-хук Hysteria может вернуть **произвольный id**, и по нему дальше идут `/online`, `/traffic`, `/kick` | Слоты технически возможны |
| Hysteria считает **соединения**, а не адреса: два клиента с одного адреса на одном креде дают `{"user": 2}` | За NAT устройства различимы — то, чего нет у остальных движков |
| **Отказ в auth работает чисто**: второй получает `authentication error`, занявший слот не шелохнулся | Правило слота — отказ |
| **Вытеснение не работает**: кик из auth убивает и новичка, слот остаётся пустым | Вытеснение из плана убрано |
| Кик по id не трогает соседний id | Слоты изолированы друг от друга |
| `statsonline` Xray = уникальные **адреса**: два клиента с одного адреса на одном креде дают `online=1` | Xray за NAT слепой |
| В clash API sing-box соединение = отдельный поток, `metadata.user` пуст ([P-17](../../issues/PROTOCOLS.md#p-17)) | TUIC за NAT слепой |

Вывод: **жёсткий слот возможен только на Hysteria.** Xray и TUIC остаются
мягкими (счётчик + заморозка), и это не лечится в рамках их API.

## 3. Ключевое решение: id остаётся именем юзера

Первая версия замысла давала каждому слоту свой id (`user.1`, `user.2`) — и
упиралась в то, что на id завязан весь учёт: трафик, онлайн, кик, tc-классы,
`authmap`, публикация в кластер, API надстройки. Это 18 файлов, и в каждом
пришлось бы суммировать слоты обратно в юзера.

Решение: **auth-хук возвращает прежний id — имя юзера.** Слот опознаётся по
паролю и проверяется внутри самого хука, наружу не протекает. Учёт не меняется
ни в одном месте.

```
клиент → user:<пароль слота N> → hysteria-auth.sh
                                   ├── пароль не совпал ни с одним слотом → отказ
                                   ├── слот N занят другим адресом          → отказ
                                   └── иначе → печатает "user", код 0
```

Цена решения: снаружи не видно, какой слот сколько потребил. Пер-слотовый учёт
не заказан, а появится нужда — это отдельный разговор, не блокер.

## 4. Как слот понимает, что он занят

Auth-хук зовётся на **подключение**, а не постоянно: узнать «сессия ещё жива»
изнутри него нельзя. Поэтому берём уже существующие данные: `refresh_online()`
раз в минуту собирает живой набор адресов юзера (`lib/online.sh`), а
`enforce_device_limits` уже пишет снимок для auth (`write_authlimits`).

* слот помнит адрес, с которого его заняли (свой файл, строка `user|slot|ip|ts`);
* слот **свободен**, если его адреса нет в живом наборе онлайна;
* слот **занят**, если адрес в наборе есть и он **не равен** тому, кто стучится.

Тот же адрес пускается всегда: переподключения и параллельные соединения одного
устройства (браузер держит их десятками) слот не расходуют.

Задержка снимка — до минуты. Отсюда два честных следствия, оба приемлемы:
устройство, сменившее сеть, до минуты видит свой прежний слот занятым (займёт
любой свободный), а освободившийся слот до минуты держится за ушедшим. Точность
можно поднять, если хук будет сам подтверждать разрыв, — не в первой версии.

## 5. Где живут пароли слотов

Скелет уже есть: у юзера может быть **несколько токенов подписки**
(`sub_link_add`, `lib/sub_links.sh`), и их число уже ограничено количеством
устройств (`sub_links_allowed`). Сегодня все токены отдают одинаковые креды —
они нужны только чтобы различать людей по логам Caddy.

Слоты доводят это до конца: **токен N отдаёт креды слота N**. Ссылка на
устройство = существующая доп. ссылка, у которой внутри свой пароль.

Пароль слота выводится детерминированно из секрета ноды, имени юзера и номера
слота — хранить отдельную таблицу не нужно, любая нода кластера получит те же
пароли. Хук не должен считать хеши на каждое подключение (это форк на слот при
каждом коннекте), поэтому пароли материализуются в файл-справочник рядом с
`users.db` и обновляются там же, где сейчас пересобирается `users.db`.

Число слотов = число устройств юзера. Растёт лимит — добавляются слоты; падает —
лишние слоты и их токены перестают работать.

## 6. Что будет с остальными протоколами

| Протокол | Слоты | Поведение при превышении |
|---|---|---|
| Hysteria | да, жёстко | отказ в аутентификации |
| VLESS / Trojan / SS (Xray) | креды по слотам возможны, отказа нет | как сейчас: счётчик по адресам + заморозка |
| TUIC (sing-box) | ни слотов, ни отказа | как сейчас: закрытие потоков по однозначным адресам |

Значит клиент, выбравший Xray или TUIC, жёсткого слота не почувствует. Это не
недоделка, а потолок их API — держать в голове при обещаниях в продаже.

## 7. Фазы

| Фаза | Что делаем | Готово, когда |
|---|---|---|
| A | Слоты в подписке: токен N → свои креды, справочник паролей, число слотов = число устройств | Две ссылки одного юзера дают разные пароли, обе работают |
| B | Отказ на занятом слоте в `hysteria-auth.sh` + учёт занятости по живому онлайну | Третье устройство при лимите 2 получает `authentication error`, первые два не замечают |
| C | Слоты в мини-аппе: список устройств, своя ссылка и QR на каждое, отзыв слота | Покупка устройства сразу даёт ссылку |

Фазу B не включать, пока по `limit.log` не разобраны те, у кого лимит занижен:
сегодня они живут в тряске, а после B получат честный отказ — это заметно
резче. Разбор — [../../guide/DEVICE-LIMITS.md](../../guide/DEVICE-LIMITS.md) §4.2.

## 8. Что придётся править

| Файл | Зачем |
|---|---|
| `lib/sub_links.sh` | токен → номер слота, выдача кредов слота в подписке |
| `lib/protocols.sh` | сборка справочника паролей слотов, креды слотов в конфигах Xray |
| `lib/users.sh` | пересборка справочника при смене пароля/лимита юзера |
| `hysteria-auth.sh` (`install_auth_script`) | проверка пароля по слотам, занятость, отказ |
| `lib/online.sh`, `lib/devlimits.sh` | снимок «живые адреса юзера» для хука |
| `webapi/`, `надстройка` | список слотов и ссылок в мини-аппе (фаза C) |
