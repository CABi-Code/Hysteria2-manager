# Приём рублей через ЮMoney (личный кошелёк)

Продажа тарифов за рубли **без платёжного провайдера**: не нужны ни юрлицо/ИП,
ни модерация ЮKassa/Stripe, ни публичный домен. Достаточно личного кошелька
ЮMoney — бот формирует ссылку на оплату сам, а факт платежа опознаёт по метке в
истории операций кошелька.

Способ рассчитан на маленькие установки. Для оборотов, где нужна касса и чеки по
54-ФЗ, по-прежнему используйте провайдера BotFather (меню бота → 5).

## Как это работает

ЮMoney даёт публичный quickpay («API для сбора денег»). Из его устройства
следуют три ограничения, они и определяют схему:

1. **Счёта на стороне ЮMoney нет.** Ссылка на оплату — это просто набор
   параметров; при её создании никакого запроса к ЮMoney не делается, и ссылка
   не «протухает».
2. **Идентификатора платежа до оплаты нет.** Единственная связь платежа с
   покупателем — метка `label`, которую придумывает бот и кладёт в ссылку. Она
   же возвращается в истории операций.
3. **Плательщик ничем не подтверждён.** По ссылке может заплатить кто угодно и
   любую сумму — поэтому бот сверяет пришедшую сумму с ценой тарифа.

Подтверждение оплаты — **опросом истории операций** по метке. HTTP-уведомления
ЮMoney здесь сознательно не используются: они требуют публичный HTTPS-эндпоинт,
а менеджер должен работать и за NAT без домена (бот живёт на long polling).

### Цикл покупки

1. Клиент выбирает тариф с ценой в **RUB**. Если провайдер BotFather не настроен,
   а кошелёк ЮMoney задан — бот выставляет счёт ЮMoney.
2. `bot_ym_invoice` генерирует метку `<префикс>-<16 hex>`, считает сумму к
   оплате, кладёт строку в `$DATA_DIR/ympay.dat` и шлёт сообщение с двумя
   кнопками: «💳 Оплатить» (ссылка) и «✅ Проверить оплату».
3. Клиент платит на странице ЮMoney.
4. Оплату находит либо крон (`--ym-poll`, раз в минуту), либо сам клиент кнопкой
   «Проверить оплату» — это один и тот же код `ym_settle`.
5. `ym_settle` сверяет сумму и зовёт `bot_fulfill_payment` — тот же фулфилмент,
   что у Stars и провайдера: создание/продление пользователя, лимит устройств,
   привязка Telegram, запись в `payments.log`, карточка доступа клиенту и
   уведомление админам.

### Деньги: почему к оплате больше цены

Комиссию ЮMoney берёт **с получателя** и считает от переведённой суммы: карта
(`AC`) — 3 %, кошелёк ЮMoney (`PC`) — ≈0.99 %. Значит на кошелёк приходит
меньше, чем перевёл покупатель, и продавать по «голой» цене — работать в минус.

Поэтому счёт выставляется на

```
сумма = цена / (1 − YM_FEE/100)          # ym_pay_sum
```

Именно **деление**: «цена + 3 %» даёт недобор (1000 → 1030 → на кошелёк 999.10).
При `YM_FEE=3` и цене 1000 ₽ покупатель переводит 1030.93 ₽, на кошелёк приходит
≈1000.01 ₽. Ставьте процент не меньше реальной комиссии выбранного `YM_TYPE`.

### Сверка суммы

В истории операций поле `amount` — уже **зачисленное** (после комиссии), поэтому
сравнивается с ценой тарифа, а не с суммой из ссылки. Допуск — копейка
(округления с обеих сторон).

- пришло ≥ цены → доступ выдаётся;
- пришло меньше → доступ **не** выдаётся, админам уходит уведомление с меткой и
  суммой, счёт снимается с ожидания (разбор вручную);
- операции со статусом `refused` и `in_progress` оплатой не считаются.

Идемпотентность — по `operation_id`: в `payments.log` он пишется как
`ym:<operation_id>`, и перед выдачей бот проверяет журнал. Повторный опрос,
двойное нажатие кнопки или перезапуск бота доступ второй раз не продлят.

## Настройка

Меню менеджера: **Настройки → Telegram-бот → 10. 🪙 ЮMoney**.

| Ключ (`bot.conf`) | Смысл |
|---|---|
| `YM_WALLET` | номер кошелька-получателя (пусто → способ выключен) |
| `YM_TOKEN` | OAuth-токен со scope `operation-history` |
| `YM_FEE` | комиссия сервиса, % (см. выше; по умолчанию 3) |
| `YM_TYPE` | `AC` — карта (по умолчанию), `PC` — кошелёк ЮMoney |
| `YM_PREFIX` | префикс метки: на один кошелёк могут принимать несколько проектов |

Способ включается, когда заданы **и кошелёк, и токен**: без токена подтвердить
оплату нечем, и деньги уходили бы «в никуда».

### Как получить токен operation-history

Разово, руками:

1. Зарегистрируйте приложение: https://yoomoney.ru/myservices/new. Поля:
   название для пользователей, адрес сайта, почта для связи, **Redirect URI**,
   логотип и галочка «проверка подлинности». На выходе — `client_id`, а с
   галочкой ещё `client_secret`. В качестве `redirect_uri` подойдёт любой ваш
   адрес (даже несуществующий — код придёт в адресной строке браузера).
2. Откройте в браузере и подтвердите доступ:
   ```
   https://yoomoney.ru/oauth/authorize?client_id=<CID>&response_type=code&redirect_uri=<RURI>&scope=operation-history
   ```
3. Из адреса редиректа возьмите `code=` и обменяйте на токен:
   ```bash
   curl -s https://yoomoney.ru/oauth/token \
     -d "code=$CODE" -d "client_id=$CID" -d "grant_type=authorization_code" \
     -d "redirect_uri=$RURI" -d "client_secret=$CSECRET"
   ```
4. Полученный `access_token` живёт **3 года** (токены, выданные до 07.02.2018, —
   полгода). Он даёт **только чтение истории** — переводить деньги им нельзя.
   Хранится в `bot.conf` (права 600).

Тарифы должны иметь цену в валюте `RUB` (меню бота → 4). Мультивалютный тариф
(например `100/499|XTR/RUB`) даёт клиенту выбор: звёзды или карта.

Если задан и провайдер BotFather, и кошелёк ЮMoney — **выигрывает провайдер**:
у него оплата внутри Telegram и чеки.

## Компоненты

| Файл | Роль |
|---|---|
| `lib/yoomoney.sh` | вся логика: настройки, сумма, метка, ссылка, опрос истории, `ym_settle`, `ym_poll` |
| `lib/tgbot_client.sh` | `bot_ym_invoice` — счёт с кнопками; ветка RUB без провайдера |
| `lib/tgbot_daemon.sh` | кнопка «Проверить оплату» (`ymchk:<label>`) |
| `lib/tgbot_menu.sh` | пункт меню настройки (кошелёк, токен, комиссия, тип) |
| `lib/cron.sh`, `hy2-manager.sh --ym-poll` | опрос раз в минуту |
| `tests/test-yoomoney.sh` | суммы, метки, сверка, идемпотентность, TTL |

Данные: `$DATA_DIR/ympay.dat` — ждущие оплаты счета
(`label|создан_ts|tg_id|код_тарифа|пользователь|сумма|цена`), строки старше 48 ч
вычищаются. Журнал оплат — общий `payments.log`.

## Ограничения и грабли

- **Личный кошелёк — не касса.** Чеков нет, статус самозанятого/ИП и налоги —
  на вашей совести. Лимиты и статус кошелька (идентификация) ограничивают
  оборот — смотрите правила ЮMoney.
- **Оплату видно не мгновенно**: до минуты крон плюс задержка появления операции
  в истории. Кнопка «Проверить оплату» ускоряет только опрос, а не саму ЮMoney.
- **Переплата** зачисляется как обычная оплата тарифа — разницу вернуть надо
  вручную.
- **Платёж без метки** (клиент перевёл на кошелёк напрямую) бот не найдёт: метка
  — единственная связь платежа с покупателем.
- **Токен в `bot.conf`** — файл с правами 600 на сервере. Компрометация даёт
  чтение истории кошелька, но не переводы.

## Как расширять

- **Выбор карта/кошелёк самим клиентом** → передавать `paymentType` в
  `bot_ym_invoice` и хранить его в строке счёта: комиссии разные, значит сумму
  считать по своему проценту.
- **HTTP-уведомления** (мгновенное зачисление) → нужен публичный HTTPS. Точку
  входа логично повесить на уже существующий Web API (`webapi/`), проверка
  подписи — HMAC-SHA256 по всем параметрам кроме `sign`, ключ из настроек
  кошелька. Выдачу звать всё тем же `ym_settle`/`bot_fulfill_payment`.
- **Пополнение баланса внешнего биллинга** (мини-апп поверх Web API) — отдельная
  история: метку выдаёт и сверяет тот, кто ведёт баланс, менеджер в этом не
  участвует.
